# SushiVIP 部署执行说明

> 从零到平板上跑起来的完整操作手册。按阶段顺序执行，每步都给了验证方法。
> 配套文档：项目根目录 [`README.md`](../README.md)（技术说明）、[`doc/readme.md`](readme.md)（原始需求）

---

## 零、先看这里：角色与前置条件

| 阶段 | 谁来做 | 需要什么 |
|---|---|---|
| 一、服务器上 HTTPS | 运维 | 宝塔面板管理员权限、SSH |
| 二、CA 入工程 | Android 开发 | 运维产出的 `ca.crt` |
| 三、编译 debug 包 | Android 开发 | Android Studio + JDK 17 + SDK 35 |
| 四、真机验证 | Android 开发 + 现场 | 目标平板、USB 线、内网 Wi-Fi |
| 五、前端对接 | 前端 | 阶段四通过后进行 |
| 六、正式发布 | Android 开发 | keystore（本阶段生成） |

**关键依赖关系**：阶段一不完成，阶段四的扫码功能一定跑不起来。
不要跳过阶段一直接测扫码，那是在浪费时间排查一个不存在的 bug。

## 阶段一：服务器上 HTTPS（运维执行）

### 为什么必须做

站点跑在 `http://` 上时，Chromium 不把它当作「安全上下文」，
`navigator.mediaDevices` **直接是 `undefined`** —— 网页扫码在技术上不可能工作，
和权限、和 App 代码都无关。这是浏览器内核的硬性规则，客户端绕不过去。

顺带说明：`crypto.subtle`（前端加解密）、Service Worker、剪贴板 API、
地理定位，在 `http://` 下同样全部不可用。上 HTTPS 一次性解决全部。

### 1.1 生成证书

在服务器上（或任意一台 Linux）执行：

```bash
git clone <本仓库地址>
cd apksomv1
./tools/gen-intranet-cert.sh lms.sushisom.net 192.168.2.32
```

产出目录 `certs-lms.sushisom.net/`，共 4 个文件：

| 文件 | 用途 | 去向 |
|---|---|---|
| `fullchain.pem` | 完整证书链 | 宝塔「证书(PEM格式)」 |
| `server.key` | 服务器私钥 | 宝塔「密钥(KEY)」 |
| `ca.crt` | 内部根 CA 证书 | 交给 Android 开发 |
| `ca.key` | **CA 签发私钥** | **拷到离线介质，然后从服务器删除** |

> **第二个参数 `192.168.2.32` 不要省。** 它会把 IP 一并写进证书的 SAN，
> 这样在没配 hosts 的机器上也能用 `curl https://192.168.2.32/` 做验证，
> 不用重新签发证书。

### 1.2 宝塔挂证书

宝塔面板 → **网站** → 找到 `lms.sushisom.net` → **设置** → **SSL** →
切到 **「其他证书」** 标签页：

| 输入框 | 粘贴内容 |
|---|---|
| 密钥(KEY) | `server.key` 的**全文** |
| 证书(PEM格式) | `fullchain.pem` 的**全文** |

点「保存」，然后打开「**强制HTTPS**」开关。

> ⚠️ **证书(PEM格式) 要粘 `fullchain.pem`，不是 `server.crt`。**
> 宝塔需要完整证书链，只粘服务器证书部分机型会握手失败。

### 1.3 放行 443 端口

```bash
sudo ufw allow 443/tcp
```

宝塔面板 → **安全** → 确认 443 在放行列表里。

### 1.4 验证（必做）

在**内网任意一台 Linux/Mac** 上：

```bash
curl -v --cacert ca.crt https://lms.sushisom.net/
```

**通过的标志**：返回 HTTP 200，且输出里有
`SSL certificate verify ok`，没有任何 `certificate problem` 字样。

再检查证书内容对不对：

```bash
openssl s_client -connect lms.sushisom.net:443 -servername lms.sushisom.net </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -dates -ext subjectAltName
```

**SAN 里必须同时出现** `DNS:lms.sushisom.net` 和 `IP Address:192.168.2.32`。

### 1.5 收尾

把 `ca.key` 拷到离线介质（U 盘/密码管理器），然后**从服务器上删除**：

```bash
shred -u certs-lms.sushisom.net/ca.key
```

### ❌ 本阶段要避免的

| 不要做 | 为什么 |
|---|---|
| 用宝塔的 **Let's Encrypt** 标签页 | 它要走公网 80 端口验证域名。`lms.sushisom.net` 由路由器 DNS 重写指向内网主机，公网上不存在，验证必然失败，纯属浪费时间 |
| 把 `ca.key` 留在服务器上或提交进仓库 | 它泄露 = 任何人都能签出被这个 App 信任的证书，中间人攻击门户大开 |
| 自己手搓 openssl 命令、跳过 SAN | Chromium 早已**不再读取 CN 字段**，只认 SAN。缺 SAN 会报 `ERR_CERT_COMMON_NAME_INVALID` |
| 证书没验证通过就往下走 | 阶段四会以「证书不受信任」失败，你会去排查 App，但问题在服务器 |

## 阶段二：把 CA 放进工程（Android 开发执行）

### 2.1 替换占位证书

```bash
cp certs-lms.sushisom.net/ca.crt app/src/main/res/raw/intranet_ca.crt
```

### 2.2 确认替换成功

```bash
openssl x509 -in app/src/main/res/raw/intranet_ca.crt -noout -subject
```

**必须**看到你自己的 `CN = Intranet Root CA`。

如果显示 `CN = PLACEHOLDER - REPLACE WITH REAL INTRANET CA`，说明**没替换成功**，
App 装上去会停在「HTTPS 证书不受信任」错误页。

> 这张占位证书的私钥在生成时就已销毁，任何人都无法用它签发证书，
> 所以不存在安全风险。它的作用是让「忘记替换」这个错误**明确报出来**，
> 而不是静默降级成不安全连接。

### 2.3 提交

```bash
git add app/src/main/res/raw/intranet_ca.crt
git commit -m "替换为内网真实根 CA"
```

## 阶段三：编译 debug 包（Android 开发执行）

### 3.1 打开工程

Android Studio → **Open** → 选择仓库根目录（**不是** `app/` 子目录）。

首次 Sync 会下载 Gradle 8.14.3 和依赖，需要能访问 `dl.google.com` 和 Maven Central。

### 3.2 如果 Sync 报 AGP 版本不兼容

工程锁的是 AGP 8.9.1 + Gradle 8.14.3。你的 Android Studio 版本较新时可能提示升级：

- 菜单 **Tools → AGP Upgrade Assistant** → 按提示一键升级
- 或手动改 `gradle/libs.versions.toml` 里的 `agp` 和 `kotlin` 版本号

### 3.3 编译

```bash
./gradlew assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

### ❌ 本阶段要避免的

| 不要做 | 为什么 |
|---|---|
| 把 `targetSdk` 升到 36 | 从 targetSdk 36 起，系统会在大屏设备（最小宽度 ≥ 600dp，即你们的平板）上**忽略 `screenOrientation`**，横屏锁定直接失效，平板会随重力乱转 |
| 改 `applicationId` | 装机之后再改等于换了一个应用，所有平板必须**卸载重装**，且设备 ID 会全部变化 |
| 删掉 `proguard-rules.pro` 里的 keep 规则 | release 包的 `getDeviceId()` 会被 R8 裁掉，前端调用时报 `not a function`，而 debug 包一切正常 —— 这种只在正式包复现的问题极难查 |

## 阶段四：真机验证（关键阶段）

### 4.1 平板准备

1. 连上**内网 Wi-Fi**
2. 开启「允许安装未知来源应用」和「USB 调试」（设置 → 关于平板 → 连点版本号 7 次进开发者模式）

### 4.2 安装

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### 4.3 验收清单（逐项确认，全部通过才算完成）

| # | 检查项 | 期望结果 | 不通过时看 |
|---|---|---|---|
| 1 | 启动 App | 显示白底 + 红色 logo + 转圈，随后进入 LMS 页面 | 故障表 A/B/C |
| 2 | **屏幕方向** | 横屏，**充电口在右侧**，转动平板不会翻转 | 故障表 D |
| 3 | 系统栏 | 状态栏和导航栏都隐藏，从边缘上滑可临时呼出 | — |
| 4 | 屏幕常亮 | 静置几分钟不熄屏 | — |
| 5 | **HTTPS** | 页面正常加载，不出现证书错误页 | 故障表 B |
| 6 | **设备 ID** | 见 4.4 | 故障表 H |
| 7 | **相机扫码** | 见 4.5 | 故障表 E/F/G |
| 8 | 返回键 | 页面能后退时后退；首页再按弹「确认退出」 | — |
| 9 | 断网启动 | 关 Wi-Fi 后启动 App，弹「网络未连接」对话框，有重试/退出 | — |
| 10 | 错误页 | 临时停掉 nginx 后重试，显示红色感叹号错误页 + 错误码，**不是**浏览器默认错误页 | — |

### 4.4 验证设备 ID

平板用 USB 连电脑，电脑 Chrome 打开 `chrome://inspect`，找到 SushiVIP 的
WebView 点 **inspect**，在 Console 里执行：

```js
window.AppBridge.getDeviceId()
```

应返回一个非空字符串（正常是 16 位十六进制）。

> debug 包才能被 `chrome://inspect` 调试，release 包已关闭该开关。

### 4.5 验证相机链路

**这是最容易出问题的一步，按顺序排查。**

在同一个 Console 里，先确认安全上下文：

```js
console.log('secure:', window.isSecureContext);
console.log('mediaDevices:', !!navigator.mediaDevices);
```

- 两个都为 `true` → 继续下一步
- `secure` 为 `false` → **阶段一没做完**，站点还在 HTTP 上，回头看阶段一

再实际取流：

```js
navigator.mediaDevices.getUserMedia({ video: { facingMode: 'environment' } })
  .then(s => console.log('OK', s.getVideoTracks()[0].label))
  .catch(e => console.error('FAIL', e.name, e.message));
```

首次执行会弹出系统的相机权限对话框，点「允许」后应打印 `OK`。

## 阶段五：前端对接（前端执行）

**前提：阶段四全部通过。** 阶段四没过就动前端，等于在流沙上盖房子。

### 5.1 设备唯一标识

```js
const deviceId = window.AppBridge.getDeviceId();  // 同步返回，保证非空
```

⚠️ **`ANDROID_ID` 按「应用签名 + 用户 + 设备」派生，所以 debug 包和
release 包在同一台平板上拿到的 ID 是不同的。**
联调阶段用 debug 包建的设备档案，换成正式包后全部对不上号。
**后端正式建档必须用 release 包采集的 ID。**

### 5.2 扫码

站点上了 HTTPS 后，直接用标准 Web API，容器已配好全部支撑：

```js
const stream = await navigator.mediaDevices.getUserMedia({
  video: { facingMode: 'environment' }
});
```

容器侧已处理：Manifest 权限声明、运行时权限动态申请、`onPermissionRequest` 放行、
以及视频流自动播放开关。

### 5.3 拍照上传

```html
<input type="file" accept="image/*" capture="environment">
```

容器已实现完整的文件选择链路：带 `capture` 直接开相机，不带则弹「相机/相册·文件」二选一，
也支持 `multiple` 多选。

### 5.4 站外链接

站外的 http(s) 链接、以及 `tel:` `mailto:` `weixin://` `alipays://` 等
都会被转交给系统处理，**不会**留在容器内。如果有链接需要留在 App 里打开，
把它的域名加进 `app/build.gradle.kts` 的 `HOST_WHITELIST`。

### ❌ 本阶段要避免的

| 不要做 | 为什么 |
|---|---|
| 往 `AppBridge` 里加方法 | `addJavascriptInterface` 注入的对象对页面内**所有** iframe 可见，包括第三方内容。每多一个方法就多一份被滥用的面。需求 3.4 明确限定只暴露取 ID |
| 指望客户端关掉 CORS | **原生 WebView 没有任何开关能关闭 CORS**。跨域由服务端 `Access-Control-Allow-Origin` 决定。已处理的是「混合内容」，那是另一回事 |
| 用 debug 包的 deviceId 灌生产库 | 见 5.1 |
| 页面里写死 `http://` 的绝对 URL | HTTPS 页面里的 http 子资源虽然放行了，但会拖慢加载且不必要。用相对路径 |

## 阶段六：正式发布

### 6.1 生成 keystore

Android Studio → **Build** → **Generate Signed App Bundle / APK** → 选 **APK** →
**Create new...** 填写并保存 keystore。

**keystore 文件和口令妥善保管。** 丢了就无法给已装机的平板做覆盖升级，
只能全部卸载重装，且所有设备 ID 会变。

### 6.2 配置签名

口令写进 `local.properties` 或环境变量，**不要提交进仓库**
（`.gitignore` 已排除 `*.jks` / `*.keystore`）。

### 6.3 编译

```bash
./gradlew assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`

### 6.4 发布前最后一次收紧

确认阶段一的证书已稳定运行后，把
`app/src/main/res/xml/network_security_config.xml` 里的

```xml
<domain-config cleartextTrafficPermitted="true">
```

改成 `cleartextTrafficPermitted="false"`，彻底关掉明文 HTTP 回退，然后重新打包。

### 6.5 分发与升级

- 内网侧载：把 APK 放到内网可下载的位置，平板浏览器下载安装
- **覆盖升级要求签名一致**。debug 包和 release 包签名不同，**不能互相覆盖**，必须先卸载
- 卸载重装（同签名 release 包）设备 ID 不变；debug ↔ release 互换则会变

## 七、日常维护

| 事项 | 周期 | 操作 |
|---|---|---|
| 服务器证书续期 | 10 年后 | 用同一个 `ca.key` 重签 `server.crt`，只需更新宝塔，**APK 不用重打包** |
| 根 CA 续期 | 10 年后 | 重新生成 CA → 更新服务器证书 → 替换 `res/raw/intranet_ca.crt` → 重新打包并全部平板升级 |
| 改目标地址 | 按需 | 改 `app/build.gradle.kts` 的 `BASE_URL`，同步更新 `HOST_WHITELIST`，重新打包 |
| 换 logo | 按需 | `cp 新logo.png doc/logo.png && python3 tools/gen_launcher_icons.py doc/logo.png` |

> 用**内部 CA 签发**服务器证书的最大好处就在这里：服务器证书随时可换，
> 只要 CA 不变，APK 就不用重新分发。

## 八、故障速查表

| 编号 | 症状 | 原因 | 处理 |
|---|---|---|---|
| **A** | 一直转圈，最后弹「网络未连接」 | 平板没连上内网 Wi-Fi | 检查 Wi-Fi |
| **B** | 错误页显示「HTTPS 证书不受信任」 | `res/raw/intranet_ca.crt` 还是占位证书，或与服务器证书不匹配 | 回阶段二，用 `openssl x509 -noout -subject` 确认 |
| **C** | 错误页显示「无法解析服务器地址」 | 平板没走路由器的 DNS。常见于手动配了静态 IP+公共 DNS，或「私人 DNS」被设成了指定主机名（如 `dns.google`） | 设置 → 网络 → 私人 DNS，确认是「关闭」或「自动」，**不要**填具体主机名。仍不行则用 `adb shell ping lms.sushisom.net` 确认解析 |
| **D** | 横屏了但**充电口在左侧** | 该平板的「自然方向」与假设相反（由 OEM 决定） | 把 `AndroidManifest.xml` 里 `android:screenOrientation="landscape"` 改成 `"reverseLandscape"`，重新打包。**不用改任何代码** |
| **E** | 点扫码按钮无反应，Console 报 `navigator.mediaDevices is undefined` | 站点还在 HTTP 上，非安全上下文 | **回阶段一**。这不是 App 问题 |
| **F** | 弹出了权限框，允许后**取景框全黑** | 视频流没有自动播放 | 检查 `MainActivity` 里 `mediaPlaybackRequiresUserGesture = false` 是否还在。也可能是前端没给 `<video>` 加 `autoplay playsinline` |
| **G** | 相机权限框只弹一次，之后再也不弹 | 用户勾了「不再询问」 | App 会弹框引导跳系统设置页。或：设置 → 应用 → SushiVIP → 权限 → 相机 → 允许 |
| **H** | `window.AppBridge` 是 `undefined` | 当前页面不在白名单域名内 | 检查 `HOST_WHITELIST`。或页面被重定向到了别的域名 |
| **I** | debug 包正常，**release 包**报 `getDeviceId is not a function` | ProGuard keep 规则被删或失效 | 恢复 `app/proguard-rules.pro` 里的 keep 规则 |
| **J** | 同一台平板换包后设备 ID 变了 | debug ↔ release 签名不同 | 正常现象，见 5.1。正式建档只用 release 包 |
| **K** | 上传按钮点了**毫无反应** | 若容器代码完整则不应出现 | 确认 `FileChooserDelegate` 未被改动；用 `adb logcat -s FileChooserDelegate` 看日志 |
| **L** | 接口报 CORS 错误 | 服务端缺 `Access-Control-Allow-Origin` 响应头 | **服务端加响应头**。客户端无法绕过，别再往 App 上找办法 |
| **M** | 每次打开都要重新登录 | Cookie 被清 / 服务端 Cookie 属性问题 | 容器已开启 Cookie 持久化。检查服务端下发的 Cookie 是否带了 `Secure` 但站点仍有 http 访问，或 `SameSite` 设置过严 |

**看日志的通用方法**：

```bash
adb logcat -s MainActivity AppWebViewClient AppWebChromeClient FileChooserDelegate DeviceIdProvider
```

## 九、绝对不要做的事（汇总）

1. ❌ **不要用宝塔的 Let's Encrypt 签内网域名** —— 需要公网验证，必然失败
2. ❌ **不要把 `ca.key` 留在服务器或提交仓库** —— 泄露即失去全部 TLS 保护
3. ❌ **不要用 `onReceivedSslError` + `proceed()` 来「临时绕过」证书问题** —— 等于接受任意伪造证书，TLS 安全性归零。工程里已刻意不这么做
4. ❌ **不要把 `targetSdk` 升到 36** —— 大屏设备上横屏锁定会被系统忽略
5. ❌ **不要往 `AppBridge` 里加方法** —— 违反需求 3.4 的安全约束，扩大攻击面
6. ❌ **不要删 ProGuard 的 keep 规则** —— 只在 release 包复现的问题最难查
7. ❌ **不要用 debug 包采集的设备 ID 灌生产库** —— 换正式包后全部失效
8. ❌ **不要指望客户端能关掉 CORS** —— 原生 WebView 没有这个开关，只能改服务端
9. ❌ **不要给平板的「私人 DNS」填具体主机名**（如 `dns.google`）—— 会绕过路由器 DNS。「关闭」和「自动」都没问题
10. ❌ **不要在装机之后改 `applicationId`** —— 等于换应用，全部平板要卸载重装
11. ❌ **不要把 `BASE_URL` 改回 `http://` 然后指望扫码能用** —— 非安全上下文下 `getUserMedia` 不存在
12. ❌ **不要把 keystore 或其口令提交进仓库** —— 丢了无法覆盖升级，泄露则任何人可伪造你们的应用

## 十、快速检查清单（打印出来对着勾）
