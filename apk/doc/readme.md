# 极简 WebView 容器 Android 客户端设计与开发需求文档

## 1. 项目概述

本项目旨在开发一款极简的 Android 应用程序（APK），作为特定 Web 应用程序的专属原生容器（WebView 套壳）。应用的主要职责是提供一个无缝、全屏的 Web 浏览环境，并为前端网页提供必要的设备级底层权限支持（如相机与设备唯一标识），同时确保在异常情况下的用户体验。

## 2. 基础开发环境与参数要求

* **开发工具：** Android Studio Quail 3 (2026.1.3)
* **目标平台：** Android
* **系统支持：** 适配现代 Android 系统（建议 Target SDK 35 或以上，兼容至 Android 8.0+）。
* **目标加载地址：** 指定网址（示例参考：`[http://aaa.bbb.com](http://aaa.bbb.com)`）。由于可能涉及 HTTP 协议，系统配置必须明确允许明文网络流量（Cleartext Traffic）。

## 3. 核心功能与交互需求

### 3.1 窗口与显示规范

* **屏幕方向锁定：** 应用启动后，界面必须强制锁定为横屏显示（Landscape），并在整个应用生命周期内保持不变。
* **沉浸式体验（可选推荐）：** 隐藏顶部系统状态栏和底部导航栏，最大化展示网页内容。
* **加载过渡处理：** 在网页完全加载完成前，应显示基础的原生加载动画（如系统默认的进度圈）或保持背景色与网页主题色一致，避免长时间白屏。

### 3.2 网页容器（WebView）配置

* **基础环境支持：** 必须开启 `JavaScriptEnabled` 和 `DomStorageEnabled`，以确保现代前端框架、本地缓存（LocalStorage）及 JS 脚本的正常运行。
* **跨域与混合资源：** 需放开跨域限制，允许混合内容加载（如果在 HTTPS 环境下加载 HTTP 资源），避免网页接口被拦截。

### 3.3 硬件权限与功能映射

* **相机与扫码支持：**
* **原生层面：** 应用必须在 Manifest 中声明相机权限（`android.permission.CAMERA`），并在首次拉起时处理动态权限申请。
* **容器层面：** 必须配置并重写 `WebChromeClient` 中的权限请求回调（`onPermissionRequest`），允许网页端发出的相机调用请求（如 WebRTC 或 HTML5 相机 API），确保网页内嵌的扫码功能正常运作。



### 3.4 设备唯一标识（JS Bridge 方案）

* **标识获取：** 应用通过 Android 系统 API 获取设备的 `ANDROID_ID`（64位十六进制字符串）。
* **通信通道：** 使用 `addJavascriptInterface` 建立 JS 桥接。
* **接口契约：**
* 注入对象名：`AppBridge`
* 暴露方法：`getDeviceId()`
* 前端调用示例：`window.AppBridge.getDeviceId()`


* **安全限制：** 该 JS 接口仅暴露获取 ID 的功能，禁止在其中包含其他与当前业务无关的系统级调用。

### 3.5 异常拦截与错误处理

* **前置网络校验：** 在尝试加载指定 URL 前，检测设备是否存在可用网络。若无网络，直接阻断加载，弹出原生对话框提示“网络未连接”，并提供退出或重试按钮。
* **加载错误拦截：**
* 监听 `WebViewClient` 的错误回调（包括但不限于 DNS 解析失败、服务器 404/500 错误、连接超时等）。
* 一旦捕获到错误，必须阻止 WebView 显示默认的浏览器错误页面。
* **呈现方式：** 弹出清晰的原生错误提示框，或加载一个打包在应用内部的极简 HTML 本地错误页。



### 3.6 导航与物理按键响应

* **返回键逻辑：** 拦截 Android 设备的物理（或手势）返回键。
* 若 WebView 内部存在浏览历史且可以后退（`canGoBack()` 为 true），则执行网页的后退操作。
* 若已经是首页，再次按下返回键则弹出确认框或直接退出应用。



## 4. 权限清单 (AndroidManifest.xml 需求)

* 网络访问权限：`INTERNET`
* 网络状态读取：`ACCESS_NETWORK_STATE`
* 相机使用权限：`CAMERA`
