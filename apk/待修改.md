# APK 待修改事项

> 来自 Web 侧对着 `apk/` 源码逐条核对容器契约后的结论。
> 按优先级排列，**没有一项是阻塞上线的**——契约本身已经打通。
>
> ⚠️ 这些修改我没有代劳，原因很实在：**这台机器上没有 Android SDK
> （只有 gradle，没有 SDK/平台工具），我改了也编译不了、跑不了。**
> 把没验证过的 Kotlin 塞进你们的仓库，不如给一份能直接照做的清单。

## 先说结论：契约是通的

对着源码核对过的部分，两边完全对得上，**不需要改**：

| 契约 | APK 侧 | Web 侧 |
|---|---|---|
| 加载地址 | `BASE_URL = https://lms.sushisom.net/` | 就是 Pad 首页 ✓ |
| 设备 ID 对象名 | `addJavascriptInterface(AppBridge(...), "AppBridge")` | 桥接调 `window.AppBridge` ✓ |
| 设备 ID 方法名 | `getDeviceId()` | 同名 ✓ |
| 容器识别 | UA 追加 `SushiVIP/${VERSION_NAME}` | 桥接正则 `/SushiVIP\/([\d.]+)/` ✓ |
| 自签证书 | `res/raw/intranet_ca.crt` + `trust-anchors` | — ✓ |
| 设备 ID 长度 | ANDROID_ID 16 位 / 兜底 UUID 32 位 | 库里 `VARCHAR(40)`，装得下 ✓ |
| 横屏锁定 | `android:screenOrientation="landscape"` | 布局按横屏做 ✓ |
| 沉浸式边到边 | `setDecorFitsSystemWindows(false)` | CSS 已加 `env(safe-area-inset-*)` 避让 ✓ |

几处做法值得说一句**做对了**：

- `onReceivedSslError` 明确 `handler.cancel()` 而不是 `proceed()`，
  自签证书走 `trust-anchors` 正规信任 —— 这比无脑放行安全得多。
- `onReceivedError` / `onReceivedHttpError` 都判了 `isForMainFrame`，
  否则页面里任何一个子资源失败都会弹错误页。
- `NetworkChecker` 用的是 `NET_CAPABILITY_INTERNET` 而不是
  `NET_CAPABILITY_VALIDATED` —— 门店是内网，用后者会误判成"没网"。

## 建议改：关掉明文流量

**文件**：`app/src/main/res/xml/network_security_config.xml`

配置文件自己的注释就写着「证书上线并验证通过后，请改成 `false`」。
证书现在已经验证过了（TLS 1.3 握手成功，`CN=lms.sushisom.net`，
由 `Intranet Root CA` 签发）。

```diff
-    <domain-config cleartextTrafficPermitted="true">
+    <domain-config cleartextTrafficPermitted="false">
```

**风险评估**：Web 侧已实测**零处**绝对 `http://` 链接，
所有资源都是根相对路径（`/assets/pad.js` 这种），`BASE_URL` 也是 https。
所以关掉是安全的。

**但请留意**：万一还有哪里走 http，关掉之后表现是**静默加载失败**，
需要重新打包才能回退。建议改完先在测试机上开一遍全流程再发正式包。

## 可选：Cookie 落盘

**文件**：`app/src/main/java/net/sushisom/sushivip/MainActivity.kt`

现状：配了 `setAcceptCookie(true)`，但全文没有 `CookieManager.flush()`，
也没有 `onPause` / `onStop`。WebView 的 Cookie 是定期才落盘的，
**进程被杀时最近写入的可能还没写下去**。

影响：Pad 的登录态就是一个 12 小时的会话 Cookie。不加 flush，
应用被划走或被系统回收后，收银员需要重新登录。

**门店已确认「重新登录可以接受」，所以这条是可选的。** 想省掉这次重登就加：

```kotlin
override fun onPause() {
    super.onPause()
    // WebView 的 Cookie 是定期才落盘的，进程被杀时最近写入的可能还没写下去。
    // 登录态就是一个会话 Cookie，这里主动落一次盘，避免划掉应用就要重登。
    CookieManager.getInstance().flush()
}
```

`CookieManager` 已经 import 过了（第 12 行），不需要加新的 import。

## 可选：让 `diagnose()` 能分辨 debug / release 包

**背景**：`ANDROID_ID` 按应用签名派生，**debug 包和 release 包在同一台
平板上取到的值不同**。联调阶段用 debug 包建的设备档案，换正式包后
会全部对不上号。

现在 `versionNameSuffix = "-debug"` 让 UA 变成 `SushiVIP/1.0.0-debug`，
而前端桥接的正则 `/SushiVIP\/([\d.]+)/` 只截得到 `1.0.0` ——
`SushiVIP.container().version` 两种包看起来一样。

好在 `diagnose()` 会打印完整 UA，**能分辨，只是不够显眼**。
如果想更保险，可以在 AppBridge 上加一个方法：

```kotlin
/** 返回 "debug" 或 "release"，供前端在联调时确认包类型 */
@JavascriptInterface
fun getBuildType(): String = BuildConfig.BUILD_TYPE
```

加了告诉我，我在 `diagnose()` 里显示出来。**不加也行**，
正式建档前用完整 UA 确认一次就够。

## 需要你们拍板的一个产品问题

容器只加载 `https://lms.sushisom.net/`，也就是 **Pad 收银界面**。
管理后台在 `/cp/`，而容器**没有地址栏**，平板上没有任何入口能走过去。

目前这样是合理的（收银员本来也不该进后台）。但如果店长想在平板上
看报表、改配置，就需要一个入口。两条路：

1. **保持现状** —— 后台只在 PC 上用。推荐。
2. Pad 界面上加一个入口（只对 role ≥ 2 的账号显示）。
   这个我在 Web 侧就能做，说一声即可。

## 不用管的

- `lms.sushisom.org` 不在 `HOST_WHITELIST` 也不在证书 SAN 里 ——
  门店已确认只用 `.net`，`.org` 仅作备用且不进平板。
- `AppWebChromeClient` 没重写 `onJsAlert/onJsConfirm/onJsPrompt` ——
  Web 侧已经把全部 8 处系统对话框换成页内弹层，不再依赖这三个回调。
- 没有 `setSupportMultipleWindows` / `setDownloadListener` ——
  Web 侧实测 `window.open` 与下载入口均为 **0 处**，用不到。
