# 05 · 合规（LOPDGDD/GDPR）与 Wallet 卡分发

> 适用法域：西班牙。适用法规：GDPR（EU 2016/679）+ LOPDGDD（Ley Orgánica 3/2018）。
>
> 本文档为工程落地要求，不构成法律意见。上线前建议由本地 DPO 或律师复核。

## 1. 数据最小化

**仅采集三项 PII：手机号、邮箱、生日。无姓名。**

| 字段 | 必填 | 用途 | 备注 |
|---|---|---|---|
| 手机号 | 二选一 | 会员识别、双重确认短信 | — |
| 邮箱 | 二选一 | 会员识别、双重确认邮件 | — |
| 生日 | 选填 | 生日券 | 属画像用途，**告知中必须写明** |

手机号与邮箱**至少填一项**（否则无法发送双重确认）。

## 2. 法律依据与双重确认（Double Opt-in）

### 2.1 两类处理目的必须分开

由收银员代为注册，客人没有主动勾选同意，因此必须区分：

| 处理目的 | 法律依据 | 是否需要事前同意 |
|---|---|---|
| **积分记账、卡券发放** | 合同履行（Art. 6.1.b） | 否，可当场入账 |
| **营销推送**（促销短信/邮件） | 同意（Art. 6.1.a） | **是，必须先取得** |
| **生日券画像** | 同意（Art. 6.1.a） | **是** |

> 关键设计：**积分当场入账（客人马上要走），但在取得同意前不可用于兑换、不可用于任何营销推送。**

### 2.2 流程

```
收银员在 Pad 录入手机号/邮箱
        │
        ▼
本地库创建会员：consent_status = 0 (pending)
积分正常入账，但标记为冻结（不可兑换）
        │
        ▼
/app 立即向公网发起【出站】HTTP 请求
调用外部短信/邮件服务商 API（Twilio / AWS SNS 等）
        │
        ▼
消息内容包含：
  · 会员已创建的告知
  · 隐私政策完整链接
  · 【我同意】按钮（带 consent_token）
  · 【取消订阅 / 要求删除我的数据】按钮
        │
        ▼
客人点击同意 → consent_status = 1 (active)
             → 积分解冻，可兑换
             → 记录 consent_at / consent_ip（举证用）
        │
        ▼
30 天（可配）未同意 → consent_status = 3 (expired)
                    → 积分冻结
                    → PII 假名化（见 §4）
```

### 2.3 现场告知（不可省略）

收银员录入前必须口头告知，且 Pad 界面上需常驻一行提示：

> 「我们将为您创建会员账户，并向您的手机/邮箱发送一条包含隐私政策的确认消息。」

未经告知即录入 PII，在西班牙属高合规风险。

## 3. 数据主体权利（ARCO-POL）

必须提供落地入口与 **30 天**内响应流程：

| 权利 | 实现 |
|---|---|
| 访问 Acceso | 隐私链接页内"查看我的数据" |
| 更正 Rectificación | 隐私链接页内自助修改手机号/邮箱/生日 |
| 删除 Supresión | 隐私链接页内"删除我的数据"按钮 |
| 限制 Limitación | 暂停处理开关 |
| 携带 Portabilidad | 导出 JSON/CSV |
| 反对 Oposición | 取消营销订阅开关 |
| 撤回同意 | 与"反对"同一入口，撤回后 `consent_status = 2` |

每次权利行使**必须记入 `audit_log`**（见 `04-本地库Schema.md` §8）。

## 4. 删除 = 假名化，不是物理删除

会员要求删除时：

```
抹除：phone、email、birthday、consent_ip
保留：point_ledger 全部流水、pos_order 全部记录
     （金额、时间、积分变动 —— 会计与税务留存义务）
置位：member.pseudonymized = 1
     member.card_no 替换为不可逆哈希
```

**理由**：西班牙商法与税法要求交易记录留存数年，直接删除流水会违反留存义务；而流水本身在抹除关联 PII 后不再构成个人数据。

## 5. 留存期限

| 数据 | 留存期 | 到期动作 |
|---|---|---|
| 会员 PII | 末次消费后 **3 年** | 自动假名化 |
| 积分流水 | 按当地会计/税务要求（建议 6 年） | 归档 |
| 未同意会员的 PII | 创建后 **30 天** | 假名化 |
| 审计日志 | 3 年 | 归档 |
| 备份 | 30 天滚动 | 自动覆盖 |

留存期需写入 `sys_config` 并由定时任务执行。

## 6. 必备文档与合同

| 项 | 说明 |
|---|---|
| **RAT**（Registro de Actividades de Tratamiento） | 处理活动记录。**必须包含**：会员 PII 处理、**以及我们从 POS 只读抓取并落地到本地库的交易数据处理**（后者常被遗漏，但它确实构成对个人相关数据的处理） |
| **DPA** | 与 POS 厂商签订受托处理协议（Encargado del tratamiento） |
| **DPA（服务商）** | 与短信服务商、云对象存储服务商分别签订 |
| **隐私政策** | 公网可访问，链接嵌入所有确认消息与 Wallet 卡背面 |
| 跨境传输评估 | 若短信/存储服务商在欧盟外，需 SCC 或充分性认定 |

> 📌 我们**只读** POS 主库，这在合规上是加分项（不改变 POS 的数据处理行为）；但**把订单号与金额落到本地库已构成数据处理**，必须写进 RAT。

## 7. Apple / Google Wallet 电子卡

### 7.1 定位：仅作身份识别

卡片**只承载一个二维码**（内容为 `card_no`），供 Pad 扫描识别会员身份。**不显示积分余额、不显示等级。**

**由此带来的重大简化**：Apple Wallet 的动态更新需要 Apple 服务器**回连**卡片中声明的 `webServiceURL`，而本系统"外网不可访问门店"的策略堵死了这条路。既然只做身份识别，**使用静态 pass 即可，完全不需要 pass 更新服务**。

| 平台 | 更新机制 | 本方案 |
|---|---|---|
| Apple Wallet | 需 APNs + `webServiceURL` 入站回连 | ✅ 静态 pass，不声明 `webServiceURL` |
| Google Wallet | 通过 API 出站推送 | ✅ 静态即可（如未来需要，出站更新也可行） |

余额查询走隐私链接页（公网），与卡片解耦。

### 7.2 分发流程（全程出站）

```
/app 本地动态生成 .pkpass 文件
        │
        ▼
【出站】上传到云端对象存储（S3 / OSS）
        │  ⚠️ 上传后立即设为私有
        ▼
生成【预签名 URL】，有效期 15 分钟
        │
        ▼
【出站】通过短信/邮件 API 把签名链接发给客人
        │
        ▼
客人点击公网链接 → 下载 → 添加到手机钱包
        （全程无需从外部穿透进门店局域网）
```

### 7.3 ⚠️ 安全要求

| 要求 | 原因 |
|---|---|
| **必须用预签名 URL，不得公开可读** | `.pkpass` 内含会员标识，公开链接等于 PII 裸奔，属"未采取适当技术措施" |
| 有效期 ≤ 15 分钟 | 限制泄露窗口 |
| 上传后立即设为私有 | 防止桶策略误配导致长期暴露 |
| pass 内容最小化 | 只放 `card_no`，不放手机号、不放姓名 |
| 卡背面（Back Fields）附完整隐私政策链接 | LOPDGDD 要求；也是客人的删除数据入口 |
| 定期清理过期对象 | 减少存量暴露面 |

### 7.4 卡片内容规范

| 位置 | 内容 |
|---|---|
| 正面主字段 | 餐厅名 |
| 正面二维码 | `card_no`（纯标识，无 PII） |
| 背面 Back Fields | 隐私政策完整链接 · 「取消订阅 / 要求删除数据」链接 · 客服联系方式 |
| **不放** | 手机号、邮箱、生日、姓名、积分余额 |

## 8. 传输与存储安全

| 项 | 要求 |
|---|---|
| Pad ↔ 侧系统 | **HTTPS 强制**（见 `00-架构总览.md` §4）。局域网内明文传输 PII 同样不可接受 |
| 侧系统 ↔ POS 主库 | 局域网内 MySQL 连接，只读账号，限定来源 IP |
| 侧系统 ↔ 公网服务商 | HTTPS/TLS |
| 本地库备份 | **加密**后再推送到云端 |
| 密码/密钥 | 全部走配置文件，不入版本库，不硬编码 |
| 日志 | **禁止**在日志中打印完整手机号/邮箱，需脱敏（如 `6****789`） |
