# 12 · 多语言（中文 / 西班牙语）

> Pad 前台支持中文与西班牙语。每个人自己选，选择记在**账号**上，
> 换台平板登录还是他选的那种。
>
> 后台（CP）**没有**做多语言 —— 它只有店主和经理用，没有这个需求。

---

## 一、一句话

**语言跟着账号走，不跟着平板走。**

收银台的平板是共用的，中文和西语的员工换班轮着用同一台。
存在平板本地就变成「谁最后切的算谁的」，
而店里恰恰是每天换好几拨人。

| 场景 | 结果 |
|---|---|
| A 切成西语，下班 | A 的账号记下 `es` |
| B 用**同一台**平板登录 | 显示 B 自己的语言（他没选过 → 后台默认） |
| A 换**另一台**平板登录 | 还是西语 |
| 谁都没登录（登录页） | 这台平板上次用的语言；没切过则用后台默认 |

登录页那份存在 `localStorage` 里，因为那时**还不知道是谁**。
登录成功后一律以账号上的为准。

## 二、两处文案，各管各的

这是本方案唯一需要记住的结构。

| 在哪 | 管什么 | 为什么不合并 |
|---|---|---|
| `app/lib/Http/Api.php` 的 `MESSAGES` / `MESSAGES_ES` | **错误码对应的提示语** | 服务端本来就有一整套；前端再存一份必然漂移 |
| `wwwroot/assets/i18n.js` | **界面上的静态文字**（按钮、标题、说明） | 服务端用不着这些 |

前端**不翻译服务端的报错**，只显示 `e.message`。
Pad 每次请求带 `X-Lang`，服务端按它回话。

```
Pad ──── X-Lang: es ────▶ api.php
                          Api::setLang('es')
                          ↓
         ◀── {"error":"card_unknown",
              "message":"Esta no es una tarjeta emitida por el restaurante"}
```

> 🔴 **漂移的表现是「界面西语、报错中文」**，而现场没人会为这种
> 「小事」专门来报 —— 所以两张表的键由测试逐条比对（`tests/cases/I18nTest.php`）。

## 三、怎么加一句新文案

1. 在 `wwwroot/assets/i18n.js` 的词典里加一条，**中文和西语都要写**：

```js
'member.someNewThing': { zh: '中文文案', es: 'Texto en español' },
```

2. 用的时候：

```js
T('member.someNewThing')                       // 直接取
T('lookup.tableHint', { min: 30 })             // 带参数，词条里写 {min}
```

3. 静态 HTML 用属性，不用写 JS：

| 属性 | 作用 |
|---|---|
| `data-i18n` | 设 `textContent` |
| `data-i18n-html` | 设 `innerHTML`（文案里带 `<b>` / `<code>` 的用这个） |
| `data-i18n-ph` | 设 `placeholder` |
| `data-i18n-title` | 设 `title` |

### 🔴 三条踩过的坑

**① `data-i18n` 会吃掉元素里的子节点。**

它走的是 `textContent`，把里面的东西**整个换掉**。所以：

```html
<!-- ❌ 一切语言，输入框就没了 -->
<label data-i18n="login.name">工号<input id="login-name"></label>

<!-- ✅ 文字单独包一层 -->
<label><span data-i18n="login.name">工号</span><input id="login-name"></label>
```

这个错误**在中文界面下完全看不出来** —— 初始 HTML 是对的，
只有切一次语言才会暴露。测试里静态查了这一条。

**② JS 拼出来的 HTML 不会自己刷新。**

`I18N.applyDom()` 只管带 `data-i18n` 的静态节点。订单卡片、分配行、
结果页这些是拼出来的，切语言时要在 `refreshDynamicText()` 里各自重画。

**③ 重画时别把人填了一半的东西冲掉。**

`refreshDynamicText()` **不能**调 `startAssign()` —— 它会重置 `S.people`，
收银员已经填好的金额和选好的会员会当场清空。只是切个语言而已，
不该有这种代价。用 `renderPeople()`：金额与份数每敲一下就同步进
`S.people` 了，从状态重画不会丢东西。

### 找不到的键长什么样

`T('没写过的键')` 返回 `«没写过的键»`，**不回落中文**。
漏翻译要在西语界面上显眼地暴露出来 —— 回落只会让它一直藏着。

## 四、后台能改什么

**后台 → 配置 → 界面 → 默认语言**（`default_lang`，`zh` / `es`）：

- 登录页用哪种
- **还没选过语言**的账号登录后显示哪种

> 改它**不会影响已经选过的人** —— `operator.lang` 为 `NULL` 才叫「没选过」。
> 这就是那一列允许为 NULL 的原因：把默认语言从中文改成西语时，
> 没选过的人应该跟着变，明确选了中文的人不该被改掉。

## 五、涉及的文件

| 文件 | 作用 |
|---|---|
| `db/migrations/009_operator_lang.sql` | `operator.lang`，可空 |
| `app/lib/Lang.php` | 支持哪些语言、语言码归一（`zh-CN` / `ES` / `es_MX` 都收敛） |
| `app/lib/Http/Api.php` | 两套错误文案 + `setLang()` / `message()` |
| `wwwroot/api.php` | 每次请求定语言：**请求头 → 后台默认** |
| `app/api/routes.php` | `/auth/lang` 落库；登录与 `/auth/me` 带回 `lang` |
| `app/lib/Service/AuthService.php` | `setLang()`，以及两条取账号的路径都带 `lang` |
| `wwwroot/assets/i18n.js` | 词典 + `T()` + `applyDom()` |
| `wwwroot/assets/pad.js` | 全部界面文字改走 `T()`；`refreshDynamicText()` |
| `wwwroot/index.html` | `data-i18n` 标记 |
| `wwwroot/assets/ui.js` | 默认按钮文案跟着语言走，但**不硬依赖**词典（后台只引 ui.js） |

> `ui.js` 里的 `tr(key, fallback)` 是有意写成「有词典就用、没有就回落中文」的：
> 后台（`cp/`）引了 `ui.js` 但不引 `i18n.js`，直接引用 `I18N` 会炸。

## 六、上线要做什么

```bash
php bin/init.php migrate    # 009_operator_lang.sql，只加一列，非破坏性
php bin/init.php seed       # 加上 default_lang 配置项
```

然后把 `wwwroot/` 整个传上去 —— **`assets/i18n.js` 是新文件，别漏**。

> 漏了它的症状很好认：页面能开，但**按钮上一个字都没有**
> （`data-i18n` 的元素被设成了空），控制台报 `T is not defined`。
> 与 `ui.js` 漏传是同一类问题，见 `07` §1 第 13 条。

Pad 端强制刷新一次（见 `10` §六）。

## 七、翻译本身谁来定

西语文案是照着**收银台口语**写的：短句、直接说下一步该做什么，
不堆敬语。但**没有母语者复核过**。

建议上线前让店里的西语员工把这两处过一遍，改完直接改文件即可：

- `wwwroot/assets/i18n.js` —— 界面文字（223 条）
- `app/lib/Http/Api.php` 的 `MESSAGES_ES` —— 错误提示（58 条）

改完跑一次 `php tests/run.php`，它会检查两种语言的键是否还对得上。
