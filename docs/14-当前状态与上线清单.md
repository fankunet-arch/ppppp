## 2. 这几轮改了什么（按主题）

详细的「原来会怎样」写在 `13` 的变更表里，这里只列主题。

### 2.1 白送（店里真金白银的损失）—— 6 条

| 说的是什么 | 最坏情况 |
|---|---|
| 免费那一餐还留着计次（三条路各漏一条） | 既免了一份饭，又替这份饭攒了下一顿的进度 |
| 一桌两张券，第二张一份也扣不动 | 实付 2 份却留着 3 次；反过来收银员当场记不进去 |
| 一个打字错误 = 800 顿免费餐（发券没有上限） | 门槛 `100.00` 打成 `1.00`，一位消费 800 欧的熟客当场拿到 800 张券 |
| 赠券回收会永久卡死 | `rewards_issued` 卡住，客人白留免费餐券 |
| 同一顿饭跨餐期边界算两次 | 客人攒「十送一」的速度变快，账面上每一笔都对 |
| POS 分阶段改小同一张单，按比例分摊分子分母不同源 | 一位被退成 −77.00，另一位在 €0 的单上还留着 15 分 |

### 2.2 会卡住 / 会报错 —— 5 条

| 说的是什么 | 最坏情况 |
|---|---|
| **POS 一断线，收银台整个不能用** | 手工录入的按钮根本不显示 —— 而它正是为这一刻准备的 |
| 菜单巡检的循环没有批次上限 | 夜间 cron 永久挂起，一直占着 POS 连接 |
| 并发下「同一次退两遍」 | 每一轮都死锁；重试用完柜台就是「系统忙」 |
| cron 的并发锁按任务名取，`nightly` 与 `incremental` 会叠上 | 两个进程同时推同一条水位线 |
| 券码撞车（8 位十六进制，生日问题） | 界面显示「本地数据库暂时不可用」，而库好得很 |

### 2.3 合规 —— 1 条（这一条从 2026-08 一直躺到现在）

**假名化写不进去**：`CONCAT("ANON-", SHA1(...))` 是 45 位，
而 `member.card_no` 是 `VARCHAR(32)`。MySQL 5.7 / MariaDB 10.2.4 起默认开
`STRICT_TRANS_TABLES`，超长**不是截断，是整条 UPDATE 报错**。

于是夜间 `compliance` 任务抛异常退出，而它排在「PII 留存清理」和
「会话清理」前面 —— 三步一起不跑。**LOPDGDD 的删除义务一次都没执行过**，
运维只看到一句 MySQL 报错，看不出和个人信息有关。

> 🔴 它能躺这么久只有一个原因：**这条路整套测试一次都没走过。**
> 现在补上了（smoke 57），把「跑得完 + 真抹掉 + 流水留着」一起钉住。

### 2.4 测试方法本身 —— 4 条

- 随机化模型测试（`tests/fuzz.php`）：让机器随机组合操作，每一步查十几条不变量。
  它自己抓到了分阶段缩水、一桌两张券等好几条。
- 三种计次口径都要跑：只跑默认那一种，另外两条分支一步都没走过。
- 并发断言要盯**死锁次数**，不能只盯结果 —— 重放会把错的悄悄改对。
- 不变量不能拿被测代码算出来的数当标尺。

## 4.1 现场最常见的一句：「按桌号查不到刚买单的桌」

先跑这两条，它们会直接说是哪一条挡的：

```bash
php bin/diag.php          # ⑥ POS 主库：并排列出「主库 NOW()」与「最新一张已结账单」
php bin/why.php 30        # 逐条检验四个定位条件（结账 / 时间窗 / 堂食 / 桌号完全相等）
```

Pad 只显示【已结账 + 堂食 + 在时间窗内 + 桌号完全相等】的单，任何一条不满足
界面上都只显示「未找到」。四条里最容易误诊的是时间窗：

| 症状 | 真相 | 怎么办 |
|---|---|---|
| 这一张单确实是一小时前的 | 时间窗（出厂 30 分钟）挡住了 | 调大窗口，或让收银员用小票上的 **Factura Simplificada 号**查 —— 那条路不受时间窗限制 |
| **整个 POS 侧最近几小时一张新单都没有** | ① POS 写单的时钟与主库 `NOW()` 不是同一个（时区配错）② `pos_db` 指到了备份库或旧副本 ③ POS 停止写 `history_order_head` ④ 还没人买单 | 🔴 **不要调大窗口** —— 那只会把陈年旧单放进来，把真正的问题盖住。按 `docs/08` §0.1bis 逐条查 |

> 🔴 第一种最阴：**PHP 与 POS 的 `NOW()` 会完全一致**，
> 现有的时钟偏差告警（阈值一整天）一声不响，`/health` 也是绿的。
> 现在 `/health` 会多答一句 `pos_stale_note`，`diag`/`why` 也都会点名。

**顺带：升级完记得跑 `php bin/init.php migrate`。** 迁移没跑到的话，
接口会回 `E103`（列不存在），症状五花八门而且看不出和迁移有关。

## 6. 跑测试的注意事项

```bash
php tests/run.php                                    # 纯逻辑，随时可跑
SMOKE_DB_NAME=vip_smoke SMOKE_DB_USER=... \
  php tests/smoke.php --fresh                        # ★ 必须指向专用空库

# 随机化模型测试：改动碰了钱/券/流水就跑一轮，三种计次口径都要跑
for m in by_order once_per_period by_portion; do
  for s in $(seq 1 40); do
    SMOKE_DB_* php tests/fuzz.php $s 250 "" stable $m || break 2
  done
done

php -S 127.0.0.1:8910 -t wwwroot &                   # 探针要有站点在跑
php tests/http_sweep.php
```

- 🔴 `smoke.php --fresh` 会 `DROP TABLE`。那道「拒绝在有非 SMOKE 数据的库上 DROP」
  的闸门**不要绕过** —— 它挡的是「手滑指到了生产库」。
- 🔴 跑之前先建好 `app/config/config.php`。缺它时 smoke 的并发断言会因为
  子进程起不来而报 0，看上去像并发防护坏了（`tests/worker_boot.php` 会把这句话说出来）。
- 🔴 探针脚本跑完记得清掉自己造的 `store_code` 数据，否则下次 `--fresh` 会被闸门拦住。
