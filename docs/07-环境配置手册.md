## 2. Windows · PHP

### 2.1 必开的扩展 🔴 最容易漏

找到 `php.ini`（不确定位置就跑 `php --ini`），把这几行**前面的分号去掉**：

```ini
extension=pdo_mysql      ; 本地库
extension=mysqli         ; POS 只读（必须有，见下）
extension=mbstring       ; 🔴 漏了它，带折扣的订单一查就崩
extension=openssl        ; 登录令牌
extension=fileinfo
```

`json` 是内置的，不用管。

> 🔴 **`mysqli` 不能省。** POS 主库是 MySQL 5.5，服务端没有
> `MAX_EXECUTION_TIME`，只有 `mysqli` 的 `MYSQLI_OPT_READ_TIMEOUT`
> 能限制查询时间。`PDO::ATTR_TIMEOUT` 只管连接不管查询 ——
> 没有它，POS 一慢就会把收银拖死。

改完**必须重启 Web 服务**（宝塔/phpstudy 面板里重启 PHP，或重启 Apache/Nginx）。

验证：

```bat
php -m | findstr /i "pdo_mysql mysqli mbstring openssl"
```

四个都要出现。或者直接 `php bin\init.php repair`，第 1 步会逐个报。

### 2.2 其它 php.ini 项

```ini
date.timezone = Europe/Madrid
display_errors = Off          ; 生产环境
log_errors = On
memory_limit = 256M
post_max_size = 8M
```

时区不设的话，营业日切点（02:00）会算错。

### 2.3 php 不在 PATH

命令行报 `'php' 不是内部或外部命令` 时，用完整路径：

| 环境 | php.exe 通常在 |
|---|---|
| 宝塔面板 | `C:\BtSoft\php\82\php.exe` |
| phpstudy | `C:\phpstudy_pro\Extensions\php\php8.2.x\php.exe` |
| XAMPP | `C:\xampp\php\php.exe` |

```bat
C:\BtSoft\php\82\php.exe bin\init.php repair
```

找不到就搜：`where /r C:\ php.exe`

### 2.4 PIN 输入会回显

Windows 没有 `stty`,`php bin\init.php passwd` 时**密码会显示在屏幕上**。
这是平台限制，不是 bug —— 注意旁边有没有人。

## 3. Windows · MySQL / MariaDB

### 3.1 服务没起

**症状**：`本地数据库暂时不可用`,错误代码 `E101`。

- 宝塔/phpstudy：面板里点启动 MySQL
- 独立安装：`Win + R` → `services.msc` → 找到 MySQL → 启动
- 命令行：`net start mysql`（服务名可能是 `mysql80`、`MariaDB` 等）

设成开机自启，否则机器一重启系统就挂。

### 3.2 建库 🔴 排序规则必须显式写

```sql
CREATE DATABASE `vip_local`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;          -- 🔴 必须显式指定
```

**不能用服务器默认**：MariaDB 与 MySQL 5.7 默认 `utf8mb4_general_ci`,
MySQL 8 默认 `utf8mb4_0900_ai_ci`,没有一个等于建表用的 `utf8mb4_unicode_ci`,
会在 `WHERE 列 = @用户变量` 处报 **`1267 非法混用排序规则`**。

> 迁移文件里**没有** `CREATE DATABASE` 也没有 `USE` —— 库名是配置项，
> 写死在 SQL 里就没法改了。所以库必须先手工建。

### 3.3 账号授权 🔴 按来源主机

```sql
CREATE USER 'vip_app'@'127.0.0.1' IDENTIFIED BY '强口令';
GRANT ALL PRIVILEGES ON `vip_local`.* TO 'vip_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> 🔴 **`'u'@'localhost'` 与 `'u'@'127.0.0.1'` 是两条完全不同的授权。**
> 「命令行连得上、网页连不上」绝大多数就是这个。
> 配置里写 `127.0.0.1` 就授权 `127.0.0.1`,两边必须一致。

### 3.4 端口

默认 3306，但现场实际用的是 **3308**。配置文件里写对即可，
但要注意：**POS 主库和本地库如果同端口同实例，别把两个库搞混** ——
迁移与种子只作用于本地库，任何情况下都不要对着 `coolroid` 执行。

## 4. Ubuntu

### 4.1 装 PHP 与扩展

```bash
sudo apt update
sudo apt install -y php8.2-cli php8.2-fpm \
     php8.2-mysql php8.2-mbstring php8.2-xml php8.2-curl

php -m | grep -E 'pdo_mysql|mysqli|mbstring|openssl'
```

`php8.2-mysql` 一个包同时带 `pdo_mysql` 与 `mysqli`。

### 4.2 MySQL / MariaDB

```bash
sudo apt install -y mariadb-server
sudo systemctl enable --now mariadb        # 开机自启
sudo systemctl status mariadb
```

建库建账号同 §3.2 / §3.3。

### 4.3 时区

```bash
sudo timedatectl set-timezone Europe/Madrid
```

同时确认 `php.ini` 里 `date.timezone = Europe/Madrid`。

### 4.4 🔴 大小写敏感

**Windows 上开发、拷到 Linux 最容易踩的坑。**
Windows 文件系统不区分大小写，Linux 区分 —— 类名与文件名差一个字母，
Windows 上跑得好好的，拷过去立刻 `class not found`。

测试里有一条断言专门守这个，改动类文件后跑一遍：

```bash
php tests/run.php
```

### 4.5 权限

```bash
sudo chown -R www-data:www-data /opt/vip
sudo chmod 600 /opt/vip/app/config/config.php
sudo mkdir -p /opt/vip/var/log && sudo chmod 750 /opt/vip/var/log
```

### 4.6 用 Web 用户跑一遍诊断 🔴

```bash
sudo -u www-data php bin/diag.php
```

命令行用 root 跑能连上，不代表 `www-data` 也能 ——
MySQL 按来源主机授权，配置文件权限也可能只有 root 读得到。

## 5. Ubuntu · 宝塔面板

### 5.1 装什么

面板 → 软件商店，装：

| 组件 | 说明 |
|---|---|
| Nginx | 或 Apache |
| MySQL 5.7+ / MariaDB 10.2+ | 本地库 |
| PHP 8.2+ | |

### 5.2 PHP 扩展

**软件商店 → PHP 8.2 → 设置 → 安装扩展**,勾上：

```
pdo_mysql    mysqli    mbstring    openssl    fileinfo
```

装完在 **配置文件** 页确认 `date.timezone = Europe/Madrid`,然后**重启 PHP**。

> 宝塔默认可能没装 `mbstring` —— 就是它导致「带折扣的订单一查就崩」。

### 5.3 禁用函数 🔴 宝塔特有

宝塔默认禁用了一批函数。**PHP 设置 → 禁用函数**,确认这些**没有**被禁：

```
exec  shell_exec  proc_open  putenv
```

Cron 任务与 `bin/*.php` 需要它们。至少 `putenv` 必须放开。

### 5.4 网站与文档根 🔴

网站 → 添加站点，**运行目录必须设成 `/wwwroot`**：

```
/opt/vip/wwwroot        ← 文档根指到这里
```

> 🔴 **绝不能把文档根设成项目根。** `/app`（含数据库口令）、`/bin`、
> `/db`、`/docs`、`/tests` 都必须在文档根之外。
> 脚本自己有 `PHP_SAPI !== 'cli'` 兜底拒绝，但不要依赖它。

伪静态/URL 重写参考 `06` §4 的 Nginx 配置。

### 5.5 数据库

面板 → 数据库 → 添加数据库。**注意宝塔默认建的排序规则可能不是
`utf8mb4_unicode_ci`** —— 建完去 phpMyAdmin 里确认，不对就改：

```sql
ALTER DATABASE `vip_local`
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### 5.6 定时任务

面板 → 计划任务 → 添加，类型选「Shell 脚本」：

```bash
# 营业时段每 20 分钟
/usr/bin/php /opt/vip/bin/cron.php incremental

# 每天 03:30
/usr/bin/php /opt/vip/bin/cron.php nightly
```

具体时段见 `bin/crontab.example`。

### 5.7 nginx 不要拦截上游的错误响应 🔴

**症状**：卡号或桌号输错时，Pad 上弹出

```
服务器返回的不是 JSON（HTTP 404）
404 Not Found 404 Not Found nginx
```

收银员会以为系统坏了，其实只是号码打错。

**原因**：nginx 开着 `fastcgi_intercept_errors on;`，再配上 `error_page 404 ...`，
就会把 PHP 返回的响应体**整个换成**它自己的错误页 ——
我们写好的「这不是本店发行的会员卡」被丢掉了。

**应用侧已经修过**：业务层的「没找到」改用 HTTP 422（不在常见 `error_page`
的拦截名单里），所以这个具体症状不该再出现。

**但仍建议关掉拦截**，因为 500 / 502 / 503 一样会被吞 —— 那些场景下拿不到
我们的错误码（形如 `E202-7F3A21`），排障会难很多。站点配置里注释掉：

```nginx
# fastcgi_intercept_errors on;
```

改完 `nginx -t` 检查语法，再 `systemctl reload nginx`。

> 宝塔面板：网站 → 设置 → 配置文件，直接编辑那段 nginx 配置。

## 6. 部署清单 🔴 别只拷 wwwroot

**现场踩过**：只拷了 `wwwroot` / `app` / `bin`,`db` 目录漏了，
结果规则表是空的，所有订单显示「套餐 0 份」,还以为是门店码配错。

必须全部传到服务器：

```
项目根/
  wwwroot/     ← 网络可见（页面是 index.php，见 06 §4.1）
  app/         ← 业务逻辑 + 配置
  bin/         ← 命令行工具
  db/          ← 🔴 迁移与种子，漏了它系统跑不起来
    migrations/  001_init.sql ... 009_operator_lang.sql（9 个）
    seeds/       001_sys_config.sql ... 004_operator.sql（4 个）
  docs/        ← 可选，但建议带上
  tests/       ← 可选
  var/log/     ← 空目录，要有写权限
```

只有 `app/config/config.php` 是**每台机器各自维护**的，不跟着代码走。

传完跑一遍 `php bin/init.php repair`,它会告诉你还差什么。

`repair` / `seed` 会灌入四个账号，**初始 PIN 全是 `admin123`**：

|---|---|

## 8. 出问题时的三条命令

```bash
php bin/init.php repair          # 环境 + 表 + 配置，一次查完并尽量自修
php bin/why.php <桌号>            # Pad 上找不到订单
php bin/why.php --ref E202-7F3A21 # 按界面上的错误代码翻日志，拿到完整异常
```

错误代码对照表见 `06` §8.0。

> 🔴 **看 `check` 的输出时要数一下表的张数。**
> 这条命令曾经硬编码过一份 10 张表的名单，新加的 `card` 表不在名单里 ——
> 结果是库里少一张表，它照样报「✓ 全部 10 张表已存在」，
> 而后台发卡怎么点都没反应。名单现在跟着迁移走了，
> 但**「全绿」不等于「跑过最新的迁移」**：升级后先 `migrate` 再 `check`，
> 两条都跑。
