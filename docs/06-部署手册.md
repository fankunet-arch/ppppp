# 06 · 部署手册

## 1. 环境要求

| 项 | 要求 |
|---|---|
| PHP | **8.2+**，扩展 `pdo_mysql`、`mysqli`、`mbstring`、`json`、`openssl` |
| 本地库 | MySQL 5.7+ **或** MariaDB 10.2+（约定见 `db/README.md`） |
| Web 服务器 | Nginx / Apache，文档根指向 `/wwwroot` |
| POS 主库 | 只读账号（POS 系统中已存在），MySQL 5.5.47 |

> `mysqli` 不可省略 —— POS 主库是 MySQL 5.5，服务端**没有** `MAX_EXECUTION_TIME`，
> 只有 `mysqli` 的 `MYSQLI_OPT_READ_TIMEOUT` 能限制查询读取时间。
> `PDO::ATTR_TIMEOUT` 只管连接不管查询。

## 2. 目录与网络可见性

```
/opt/vip/
  wwwroot/          ← ★ 唯一网络可见目录，Web 文档根指向这里
    index.html        Pad 前端
    api.php           Pad API 入口
    assets/           Pad 静态资源
    cp/               管理后台（前端 + API 入口）
  app/              ← 网络不可见：全部业务逻辑
    config/config.php   实际配置（含账号密码，不入库）
    lib/  api/  cp/
  bin/              ← 网络不可见：CLI 入口
    init.php  cron.php  crontab.example
  db/               ← 网络不可见：DDL 与种子
  docs/             ← 网络不可见：设计文档
  tests/            ← 网络不可见
  var/log/          ← 网络不可见：日志
```

> ⚠️ **务必确认 `/app`、`/bin`、`/db`、`/docs`、`/tests` 不可从网络访问。**
> 最稳妥的做法是把文档根设为 `/opt/vip/wwwroot`，其余目录都在文档根之外。
> `bin/*.php` 另有 `PHP_SAPI !== 'cli'` 的兜底拒绝，但不要依赖它。

## 3. 安装步骤

### 3.1 配置

```bash
cp app/config/config.example.php app/config/config.php
vi app/config/config.php     # 填 store_code、两个数据库、短信/存储凭据
chmod 600 app/config/config.php
```

**主机地址、端口、账号全部是可变信息**（现场已发生过侧系统由
`192.168.58.128` 换到 `192.168.1.180`），一律走配置文件，代码内不硬编码。

### 3.2 环境自检

```bash
php bin/init.php check
```

逐项检查 PHP 版本与扩展、配置完整性、两个数据库的连通性、主库时钟偏差、
关键表可读性。**POS 不可达只报警告不算失败** —— 降级路径仍可用。

### 3.3 建表与种子

```bash
php bin/init.php migrate     # 建表。库中已有业务数据时会拒绝执行
php bin/init.php seed        # 配置 + 餐期 + 套餐规则，幂等可重复
```

`seed` 会把种子里的门店码 `S001` 自动替换为配置中的 `store_code`。

### 3.4 创建管理员

```bash
php bin/init.php admin admin 系统管理员
# PIN 交互输入，不回显，至少 6 位
```

PIN 用 `password_hash` 存储，**无法找回**，忘记只能重建账号。

### 3.5 定时任务

```bash
cp bin/crontab.example /tmp/vip-cron
vi /tmp/vip-cron            # 改 VIP 路径
crontab -u www-data /tmp/vip-cron
```

### 3.6 权限

```bash
chown -R www-data:www-data /opt/vip
chmod 600 app/config/config.php
mkdir -p var/log && chmod 750 var/log
```

## 4. Nginx 参考配置

```nginx
server {
    listen 443 ssl http2;
    server_name vip.example.com;      # 见 docs/00 §4：真实子域 + DNS 指内网 IP

    ssl_certificate     /etc/letsencrypt/live/vip.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/vip.example.com/privkey.pem;

    root /opt/vip/wwwroot;            # ★ 只暴露 wwwroot
    index index.html;

    # Pad API
    location /api.php { include fastcgi_params; fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/api.php;
        fastcgi_split_path_info ^(/api\.php)(/.*)$;
        fastcgi_param PATH_INFO $fastcgi_path_info; }

    # CP API
    location /cp/api.php { include fastcgi_params; fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/cp/api.php;
        fastcgi_split_path_info ^(/cp/api\.php)(/.*)$;
        fastcgi_param PATH_INFO $fastcgi_path_info; }

    # 其余 .php 一律拒绝
    location ~ \.php$ { return 404; }

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;
    add_header Referrer-Policy same-origin always;
}

# HTTP 一律跳 HTTPS —— 会员手机号等 PII 不得在局域网内明文传输
server { listen 80; server_name vip.example.com; return 301 https://$host$request_uri; }
```

## 6. 日常运维

```bash
php bin/cron.php status            # 水位线滞后与未处理告警
tail -f var/log/cron.log
tail -f var/log/php-error.log
```

后台「概览」页同样展示这些信息，水位线滞后超 72 小时会明确标红。

### 6.1 备份（硬性要求）

POS 主库只读 → 无法在 POS 上打「已积分」标记 → **本地库是幂等的唯一来源**。
本地库丢失会导致历史订单重复发分。

| 项 | 要求 |
|---|---|
| 频率 | 每日冷备 |
| 存储 | **异地**（利用「仅出站」的网络策略推到云端对象存储） |
| 加密 | 必须（含会员 PII） |
| 保留 | 30 天滚动 |
| 演练 | 定期恢复演练 |

## 7. 故障速查

| 现象 | 排查 |
|---|---|
| Pad 提示「POS 主库暂时无法访问」 | 收银流程**不受影响**，可走手工录入。查 POS 主机与网络，恢复后 Cron 会自动补抓 |
| 接口返回 `db_unavailable` | 本地库故障。这是硬故障，Pad 无法记账 |
| 输桌号查不到订单 | ① 是否超过 30 分钟窗口 ② 是否外带（不积分）③ 用「放宽到 60 分钟」④ 仍无则手工录入 |
| 后台水位线滞后 > 72 小时 | Cron 长期未成功。查 crontab、`var/log/cron.log`、锁文件 `/tmp/vip-cron/` |
| 告警「疑似 POS 数据缺失」 | **无法自愈** —— 数据本就不在主库里（实测 2024-08 曾整段丢失 6 天）。需人工核实并对该时段用手工录入补记 |
| 告警「菜单出现未归类的高价项」 | 到后台「套餐规则」页确认三个开关 |
| 收银员忘记 PIN | 管理员在后台停用后重建账号（PIN 不可找回） |
