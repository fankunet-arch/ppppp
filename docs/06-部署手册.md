# 06 · 部署手册

## 0. 关于运行平台

系统在 **Windows 与 Linux 上都能跑**，代码里没有任何平台专属假设
（测试套件里有 `跨平台` 一组断言持续把关：`posix_*` 必须有
`function_exists` 保护、调外部命令必须先判 `PHP_OS_FAMILY`、
不得硬编码盘符或 `/tmp` 之类的绝对路径、路径分隔符两种都剥）。

两个平台的差异只在运维侧：

| 项 | Linux | Windows |
|---|---|---|
| PHP 扩展 | `apt install php-mysql` | 改 `php.ini`,去掉 `extension=pdo_mysql`、`extension=mysqli` 前的分号 |
| 定时任务 | crontab（见 `bin/crontab.example`） | 任务计划程序，命令填 `php C:\wwwroot\bin\cron.php nightly` |
| 文件权限 | `chown` / `chmod` | 文件属性→安全，给 IIS/Apache 服务账号读权限 |
| 用别的身份跑诊断 | `sudo -u www-data php bin/diag.php` | 在服务账号下开命令行再跑 |
| PIN 交互输入 | 不回显（用 `stty`） | **会回显**（Windows 无 `stty`），注意旁边有没有人 |

> 🔴 **在 Windows 上开发、部署到 Linux 时最容易踩的坑是【大小写】。**
> Windows 文件系统不区分大小写，Linux 区分 —— 类名与文件名差一个字母，
> Windows 上跑得好好的，拷到 Linux 立刻 class not found。
> 测试里有一条断言专门守这个，改动类文件后跑一遍 `php tests/run.php` 即可。

---

> 📘 **装机/换机器先看 [`07-环境配置手册.md`](./07-环境配置手册.md)** ——
> Windows、Ubuntu、宝塔面板各自要设什么，以及现场真踩过的环境坑一览。
> 本文只讲部署步骤本身。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| PHP | **8.2+**，扩展 `pdo_mysql`、`mysqli`、`mbstring`、`json`、`openssl` |
| 本地库 | MySQL 5.7+ **或** MariaDB 10.2+（约定见 `db/README.md`） |
| Web 服务器 | Nginx / Apache，文档根指向 `/wwwroot` |
| POS 主库 | 只读账号（POS 系统中已存在），MySQL 5.5.47 |

> `mysqli` 不可省略 —— POS 主库是 MySQL 5.5，服务端**没有** `MAX_EXECUTION_TIME`，
> 只有 `mysqli` 的 `MYSQLI_OPT_READ_TIMEOUT` 能限制查询读取时间。
> `PDO::ATTR_TIMEOUT` 只管连接不管查询。

## 2. 目录与网络可见性

```
/opt/vip/
  wwwroot/          ← ★ 唯一网络可见目录，Web 文档根指向这里
    index.html        Pad 前端
    api.php           Pad API 入口
    assets/           Pad 静态资源
    cp/               管理后台（前端 + API 入口）
  app/              ← 网络不可见：全部业务逻辑
    config/config.php   实际配置（含账号密码，不入库）
    lib/  api/  cp/
  bin/              ← 网络不可见：CLI 入口
    init.php  cron.php  crontab.example
  db/               ← 网络不可见：DDL 与种子
  docs/             ← 网络不可见：设计文档
  tests/            ← 网络不可见
  var/log/          ← 网络不可见：日志
```

> ⚠️ **务必确认 `/app`、`/bin`、`/db`、`/docs`、`/tests` 不可从网络访问。**
> 最稳妥的做法是把文档根设为 `/opt/vip/wwwroot`，其余目录都在文档根之外。
> `bin/*.php` 另有 `PHP_SAPI !== 'cli'` 的兜底拒绝，但不要依赖它。

## 3. 安装步骤

### 3.1 配置

```bash
cp app/config/config.example.php app/config/config.php
vi app/config/config.php     # 填 store_code、两个数据库、card_prefix、短信/存储凭据
chmod 600 app/config/config.php
```

其中 `card_prefix` 是实体卡号的前缀（1~4 位字母，如 `TK`），会印在每张卡上。
**一旦印过卡就不要再改** —— 改了之后新卡与旧卡前缀不一致，盘点和手输都会乱。
见 [`09-实体卡.md`](./09-实体卡.md) §2。

**主机地址、端口、账号全部是可变信息**（现场已发生过侧系统由
`192.168.58.128` 换到 `192.168.1.180`），一律走配置文件，代码内不硬编码。

### 3.2 建库 🔴 别跳过

**迁移文件里没有 `CREATE DATABASE`，也没有 `USE`** —— 库名是配置项
（`config.local_db.database`），写死在 SQL 里就没法改了。
所以库必须先手工建好，`bin/init.php` 与 phpMyAdmin 都一样。

```sql
CREATE DATABASE `vip_local`                 -- 换成 config 里的实际库名
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;               -- ★ 必须显式指定，见下

CREATE USER 'vip_app'@'127.0.0.1' IDENTIFIED BY '换成强口令';
GRANT ALL PRIVILEGES ON `vip_local`.* TO 'vip_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> 🔴 **排序规则必须写 `utf8mb4_unicode_ci`,不能用服务器默认。**
> MariaDB 与 MySQL 5.7 默认 `utf8mb4_general_ci`、MySQL 8 默认
> `utf8mb4_0900_ai_ci`,没有一个等于建表用的 `utf8mb4_unicode_ci`,
> 会在 `WHERE 列 = @用户变量` 处报 `1267 非法混用`（详见 `db/README.md` §2.4）。

> ⚠️ **这是侧系统的本地库，不是 POS 主库。** 迁移与种子只作用于本地库，
> 任何情况下都不要对着 `coolroid` 执行。

**若用 phpMyAdmin 手工导入**（不推荐，见下）：必须先在左侧栏**点中该库**
再进 SQL 标签页，否则报 `#1046 No database selected`；
并按 `001` → `002` → `003` 的顺序导（003 依赖 001 建的 `pos_order`）。
导完还要手工补登记，否则下次 `migrate` 会重复执行并失败：

```sql
INSERT INTO `schema_migration` (`filename`,`applied_at`) VALUES
  ('001_init.sql',NOW()),('002_operator.sql',NOW()),('003_redeem.sql',NOW());
```

**推荐直接用 `php bin/init.php migrate`** —— 顺序、登记、安全闸门它都管。

### 3.3 环境自检

```bash
php bin/init.php check                    # 环境与连通性总览
sudo -u www-data php bin/diag.php         # ★ 用 Web 用户跑，定位连接问题
```

`diag.php` 专治「本地数据库暂时不可用」—— 页面上那句提示是统一兜底，
故意不显示连接串，六种完全不同的故障看起来一模一样。
`diag.php` 逐项试出来并给出对应的修复命令。

> 🔴 **务必用 Web 服务器的身份跑一遍。** MySQL 是按来源主机授权的，
> `'u'@'localhost'` 与 `'u'@'127.0.0.1'` 是两条不同的授权；
> 配置文件权限也可能只有 root 读得到。
> 「命令行连得上、网页连不上」绝大多数就是这两件事。

逐项检查 PHP 版本与扩展、配置完整性、两个数据库的连通性、主库时钟偏差、
关键表可读性。**POS 不可达只报警告不算失败** —— 降级路径仍可用。

### 3.4 建表与种子

```bash
php bin/init.php migrate     # 建表 / 增量升级
php bin/init.php seed        # 配置 + 餐期 + 套餐规则，幂等可重复
```

`migrate` 用 `schema_migration` 表记录已应用的迁移，**只跑没跑过的**，
因此上线后加新迁移（如 `003_redeem.sql`）可以直接执行，不会碰已有数据。
含 `DROP TABLE` 的迁移在库中有业务数据时仍然一律拒绝。

`seed` 会把种子里的门店码 `S001` 自动替换为配置中的 `store_code`。

### 3.5 账号

`php bin/init.php seed` 会灌入四个默认账号，**初始 PIN 全是 `admin123`**：

| 工号 | 姓名 | 角色 |
|---|---|---|
| `admin` | 系统管理员 | 管理员 |
| `manager` | 经理 | 经理 |
| `cashier1` / `cashier2` | 收银员 1 / 2 | 服务员 |

> 🔴 **上线前必须全部改掉。** 后台「操作员」页改，或 `php bin/init.php passwd <工号>`。
> 重跑 `seed` **不会**覆盖已改过的口令（`ON DUPLICATE KEY` 只更新时间戳），
> 所以不用担心把店家改过的密码重置回去。

也可以自己建：

### 3.5.1 手工创建管理员

```bash
php bin/init.php admin admin 系统管理员
# PIN 交互输入，不回显，至少 6 位
```

PIN 用 `password_hash`（bcrypt）存储，**不可逆、无法找回** —— 但可以重置：

| 场景 | 怎么做 |
|---|---|
| 自己想换 PIN | Pad 顶栏「改 PIN」/ 后台「操作员」页 → 需验旧 PIN |
| 员工忘了 PIN | 管理员在后台「操作员」页点「重置 PIN」→ 不需要旧 PIN，同时解除锁定 |
| **管理员自己忘了** | `php bin/init.php passwd <工号>` —— 需服务器 shell 权限 |

> 🔴 **`passwd` 是唯一管理员把自己锁死时的唯一恢复路径，别删。**
> 没有它的话：登不进后台建新管理员，`(store_code, login_name)` 唯一索引
> 又挡住同名重建，`audit_log` 按 `operator_id` 引用、删号会让历史审计成孤儿 ——
> 整个后台永久锁死。

改 PIN 或重置后，该账号的登录会话会被作废（自助修改保留当前这台设备），
PIN 疑似泄露时能把别人踢下线。所有改动都写审计日志。

### 3.6 定时任务

```bash
cp bin/crontab.example /tmp/vip-cron
vi /tmp/vip-cron            # 改 VIP 路径
crontab -u www-data /tmp/vip-cron
```

### 3.7 权限

```bash
chown -R www-data:www-data /opt/vip
chmod 600 app/config/config.php
mkdir -p var/log && chmod 750 var/log
```

## 4. Nginx 参考配置

```nginx
server {
    listen 443 ssl http2;
    server_name vip.example.com;      # 见 docs/00 §4：真实子域 + DNS 指内网 IP

    ssl_certificate     /etc/letsencrypt/live/vip.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/vip.example.com/privkey.pem;

    root /opt/vip/wwwroot;            # ★ 只暴露 wwwroot
    index index.html;

    # Pad API
    location /api.php { include fastcgi_params; fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/api.php;
        fastcgi_split_path_info ^(/api\.php)(/.*)$;
        fastcgi_param PATH_INFO $fastcgi_path_info; }

    # CP API
    location /cp/api.php { include fastcgi_params; fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/cp/api.php;
        fastcgi_split_path_info ^(/cp/api\.php)(/.*)$;
        fastcgi_param PATH_INFO $fastcgi_path_info; }

    # 其余 .php 一律拒绝
    location ~ \.php$ { return 404; }

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;
    add_header Referrer-Policy same-origin always;
}

# HTTP 一律跳 HTTPS —— 会员手机号等 PII 不得在局域网内明文传输
server { listen 80; server_name vip.example.com; return 301 https://$host$request_uri; }
```

## 5. 上线前必做

🔴 **测试脚本全部是命令行脚本，不要放进 `wwwroot`。**
它们和 `bin/` 下的脚本一样，用 `php` 命令在终端跑、在终端看输出，
不通过浏览器访问。`/tests` 留在文档根之外是设计的一部分（见 §2）。
每个脚本自己也会拒绝 HTTP 请求（返回 404），但那是最后一道闸，
不是可以随便摆位置的许可。

### 5.1 真库冒烟测试（MySQL 与 MariaDB 各跑一遍）

**先建一个空库**（不建会报 `#1046 No database selected`，同 §3.2）：

```sql
CREATE DATABASE vip_smoke CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

然后按平台选一种写法 —— `VAR=值 命令` 是 Linux/macOS 的 shell 语法，
**在 Windows 上不成立**：

```bash
# Linux / macOS
SMOKE_DB_HOST=127.0.0.1 SMOKE_DB_NAME=vip_smoke \
SMOKE_DB_USER=vip_app SMOKE_DB_PASS=xxx php tests/smoke.php --fresh
```

```powershell
# Windows PowerShell
$env:SMOKE_DB_HOST="127.0.0.1"; $env:SMOKE_DB_NAME="vip_smoke"
$env:SMOKE_DB_USER="vip_app";   $env:SMOKE_DB_PASS="xxx"
php tests\smoke.php --fresh
```

```bat
:: Windows cmd
set SMOKE_DB_HOST=127.0.0.1 & set SMOKE_DB_NAME=vip_smoke
set SMOKE_DB_USER=vip_app   & set SMOKE_DB_PASS=xxx
php tests\smoke.php --fresh
```

不设这些环境变量时，脚本回退到读 `app/config/config.php` 的 `local_db` ——
**那是生产库，别在上面跑 `--fresh`**。

| 参数 | 作用 |
|---|---|
| `--fresh` | 建表 + 灌种子 + 跑流程（首次必须加） |
| 不加参数 | 复用已有表，只跑流程 |
| `--keep` | 跑完不清理，便于人工翻数据 |

覆盖建表、订单定位、记账、撤销、AA 分摊、手工录入、奖励券有效期、
Cron 全流程与三项不变量校验，共 **146 项断言**。细节见 `db/README.md` §5。

**如果它拒绝执行**：`--fresh` 会 `DROP TABLE`，所以脚本先查库里有没有
`store_code <> 'SMOKE'` 的数据，有就报「拒绝执行」并退出 ——
这是闸门在正常工作，说明你指到了一个有别的数据的库。
换一个空库，或者去掉 `--fresh` 复用表结构。

## 6. 后台配置怎么改

配置页按业务分组，不是一张平铺的 key-value 表。每项都有中文标签、
一句说明和合适的控件（开关就是开关，不用填 0/1），技术参数默认折叠。

| 分组 | 放什么 | 谁最常动 |
|---|---|---|
| **奖励规则（N 送 1）** | 几送一、按次还是按金额、自动发券、券有效期、免费餐额外消费是否计入 | 店长，最常改 |
| 积分规则 | 每欧元积几分、倍率、含税与否、计次口径、撤销时间窗 | 店长 |
| 订单查找 | 桌号窗口、小票号回溯天数、核销折扣行名称 | 少动 |
| 手工录入 | 开关、单笔上限、日频告警 | 少动 |
| **界面** | Pad 的默认语言（中文 / 西班牙语） | 定一次就不动 |
| **实体卡有效期** | 提前多少天提醒换卡、过期后还能换卡的宽限期 | 定一次就不太动 |
| 合规与隐私 | 未确认保留期、PII 留存年限、营业日切点 | 基本不动 |
| 同步与巡检 | 批次、停顿、保护期（**默认折叠**） | 别动 |

改动立即生效并记入审计日志。配置项的标签与说明集中在
`app/lib/ConfigSchema.php`，**加新配置项必须在那里登记**，
否则后台会归到「未归类」—— 测试里有断言守着这个对应关系，
同时也守着「不能出现改了没效果的死配置」。

### 奖励规则改动后会发生什么

改「几次送一次」不需要任何数据迁移。达标判定用
`floor(进度 / 阈值) − 已发张数`，改完之后系统会自动把数量对齐：
调低阈值会给够条件的会员补发，调高则停发新券，**已发出去的券一律不受影响**。

改「券的有效期」同理：**只对以后发的券生效**。把 180 天改成 90 天之后，
之前按 180 天发出去的券仍然是 180 天到期 —— 客人拿到手的券，到期日不会变。

### 实体卡的两个阈值

「提前多少天提醒换卡」改完立即生效，纯粹是提醒的早晚，随便调。

「过期后还能换卡的宽限期」要当心：**缩短它等于改规则**。
卡面印的日期不会变，但客人可补救的窗口变短了 —— 这只对以后发的卡合适。
已经在客人手上的卡，按发卡当时的宽限期处理（真遇到争议，
经理可以带原因强制换发，见 `09` §9.5bis）。

卡的有效期本身是**逐张存**的，改任何配置都不会动到已经发出去的卡 ——
这是刻意设计，理由见 [`11-卡片有效期与告知.md`](./11-卡片有效期与告知.md) §4.2。

### 默认语言

「默认语言」管两件事：登录页用哪种，以及**还没自己选过语言**的账号
登录后用哪种。改它**不会影响已经选过的人** —— 每个人在 Pad 右上角
自己切换，选择记在他的账号上。详见 [`12-多语言.md`](./12-多语言.md)。

| 加密 | 必须（含会员 PII） |
| 保留 | 30 天滚动 |
| 演练 | 定期恢复演练 |

## 8. 故障速查

### 8.0 错误代码

出错时界面上会给一个代码，形如 **`E202-7F3A21`**,同时写进日志。
让收银员把它念出来或拍下来，方向立刻就清楚了。

| 前半段 | 含义 | 该查哪里 |
|---|---|---|
| `E101` | 本地库**连不上**（驱动码 2002/2003）| MySQL 服务没起 / 端口错 / 主机不可达 |
| `E105` | **口令错**,或该来源主机没被授权（1045）| ★ `'u'@'localhost'` 与 `'u'@'127.0.0.1'` 是两条不同授权 |
| `E106` | **`pdo_mysql` 扩展没装或没开** | Windows 改 `php.ini` 去掉 `extension=pdo_mysql` 前的分号 |
| `E107` | 库不存在，或该用户对这个库没权限（1044/1049）| 核对 `config.local_db.database`,或补 `GRANT` |
| `E108` | 连接数打满（1040）| 查是否有连接泄漏，或调 `max_connections` |
| `E102` | 本地库**表不存在** | 迁移没跑：`php bin/init.php migrate` |
| `E103` | 本地库**列不存在** | 迁移漏跑一个：同上；`php bin/why.php` 的 ⑤ 会点名缺哪列 |
| `E104` | 唯一键/外键冲突 | 多为并发或重复提交，看日志里的具体表 |
| `E109` | 本地库其他 SQL 错误 | 看日志原文 |
| `E201` | **POS 主库连不上或超时** | 收银不受影响，可走手工录入；查网络与 POS 主机 |
| `E202` | **POS 查询 prepare 失败** | SQL 引用了主库上不存在的列 —— 换过 POS 版本时最容易出 |
| `E203` | POS 只读护栏拦截 | 代码问题：非 SELECT / 带分号 / 没有 LIMIT |
| `E209` | 其他运行时错误 | 看日志原文 |
| `E301` | 参数类型/取值错误 | 代码问题 |
| `E309` | 未归类 | 看日志原文 |
| `B1xx` `B2xx` … | 同上，但发生在**启动期** | 连路由都没挂上，多为配置或本地库问题 |

后半段 6 位是**事件号**,每次故障独立。按它翻日志：

```bash
php bin/why.php --ref E202-7F3A21
```

会打印那一次的完整异常（类型、消息、文件行号）。
单独做这个入口是因为现场多半是 Windows,没有 `grep`。

> 🔴 **连接类故障不能只看 SQLSTATE。** 实测端口不通 / 主机不可达 / 库不存在 /
> 口令错，四种修法完全不同的故障 SQLSTATE 全是 `HY000` —— 只有驱动错误码
> （消息里 `[2002]` `[1045]` 那个）能区分。上表按驱动码分档。
> 无论哪一种，`php bin/diag.php` 都会逐项试出来并给出对应的修复命令
> （★ 记得用 Web 用户再跑一遍）。

> 🔴 **两句提示对应完全不同的原因**：`E1xx` 显示「本地数据库暂时不可用」,
> `E2xx`/`E3xx` 显示「系统内部错误」。看到后者就**不是**本地库的 SQL 问题。

> 客户端只拿到代码，**堆栈、SQL、连接串一律不外传**。



| 现象 | 排查 |
|---|---|
| Pad 提示「POS 主库暂时无法访问」 | 收银流程**不受影响**，可走手工录入。查 POS 主机与网络，恢复后 Cron 会自动补抓 |
| 页面提示「本地数据库暂时不可用」 | 跑 **`php bin/diag.php`** 直接定位。这个提示是统一兜底（不泄露连接串），六种原因长得一样：口令错 / 用户不存在 / 库不存在 / 端口错 / 主机不可达 / **授权主机不匹配**。★ 一定要再用 Web 用户跑一遍 `sudo -u www-data php bin/diag.php` —— 「命令行好好的、网页就不行」几乎都是身份差异 |
| 输桌号查不到订单 | 跑 **`php bin/why.php <桌号>`** —— 它逐条检验四个过滤条件并直说是哪一条挡的：① 单是否已结账（未结账的在 `order_head` 活单表，按设计查不到）② 是否超出时间窗 ③ 是否外带 ④ 桌号是否完全相等（会列出近期真实桌号供对照）。仍无则改用小票号查或手工录入 |
| Pad 提示「系统内部错误，请稍后重试」 | 🔴 **先分清两句提示**：「本地数据库暂时不可用」= `db_unavailable`,只在抛 `PDOException` 时给（连不上、缺表缺列/迁移漏跑）；「系统内部错误」= `server_error`,是**其余一切异常**——所以看到它就**不是本地库的 SQL 问题**,常见于 POS 侧（`RuntimeException` prepare 失败 = SQL 引用了 POS 上没有的列、`LogicException` 护栏）或 PHP 的 `TypeError`。拿原文：跑 `php bin/why.php <桌号>` 或 `php bin/why.php --invoice <小票号>`,第 ③ 步会打印异常类型/消息/文件行号/堆栈；等价的是日志里前缀 `[api]` 那行 |
| 小票号查不到订单 | 跑 **`php bin/why.php --invoice <小票号>`** 走同一条路看结论。常见两因：① 输的是 `Número Ticket` 而**不是** `Factura Simplificada`（前者当日会重号）② 提示「超过 N 天」是超出回溯上限，改后台 `invoice_lookup_max_days` 或走手工录入 |
| 后台水位线滞后 > 72 小时 | Cron 长期未成功。查 crontab、`var/log/cron.log`、锁文件 `/tmp/vip-cron/` |
| 告警「疑似 POS 数据缺失」 | **无法自愈** —— 数据本就不在主库里（实测 2024-08 曾整段丢失 6 天）。需人工核实并对该时段用手工录入补记 |
| 告警「菜单出现未归类的高价项」 | 到后台「套餐规则」页确认三个开关 |
| 收银员忘记 PIN | 管理员在后台「操作员」页点「重置 PIN」，不需要旧 PIN，同时解除连续失败锁定 |
| **管理员忘记 PIN**（登不进后台） | `php bin/init.php passwd <工号>`,交互输入新 PIN。这是唯一的恢复路径 |
| 账号被锁定（连续失败 5 次） | 等 15 分钟自动解锁；或管理员「重置 PIN」/「停用再启用」立即解锁 |
