# 06 · 部署手册

## 0. 关于运行平台

系统在 **Windows 与 Linux 上都能跑**，代码里没有任何平台专属假设
（测试套件里有 `跨平台` 一组断言持续把关：`posix_*` 必须有
`function_exists` 保护、调外部命令必须先判 `PHP_OS_FAMILY`、
不得硬编码盘符或 `/tmp` 之类的绝对路径、路径分隔符两种都剥）。

两个平台的差异只在运维侧：

| 项 | Linux | Windows |
|---|---|---|
| PHP 扩展 | `apt install php-mysql` | 改 `php.ini`,去掉 `extension=pdo_mysql`、`extension=mysqli` 前的分号 |
| 定时任务 | crontab（见 `bin/crontab.example`） | 任务计划程序，命令填 `php C:\wwwroot\bin\cron.php nightly` |
| 文件权限 | `chown` / `chmod` | 文件属性→安全，给 IIS/Apache 服务账号读权限 |
| 用别的身份跑诊断 | `sudo -u www-data php bin/diag.php` | 在服务账号下开命令行再跑 |
| PIN 交互输入 | 不回显（用 `stty`） | **会回显**（Windows 无 `stty`），注意旁边有没有人 |

> 🔴 **在 Windows 上开发、部署到 Linux 时最容易踩的坑是【大小写】。**
> Windows 文件系统不区分大小写，Linux 区分 —— 类名与文件名差一个字母，
> Windows 上跑得好好的，拷到 Linux 立刻 class not found。
> 测试里有一条断言专门守这个，改动类文件后跑一遍 `php tests/run.php` 即可。

## 1. 环境要求

| 项 | 要求 |
|---|---|
| PHP | **8.2+**，扩展 `pdo_mysql`、`mysqli`、`mbstring`、`json`、`openssl` |
| 本地库 | MySQL 5.7+ **或** MariaDB 10.2+（约定见 `db/README.md`） |
| Web 服务器 | Nginx / Apache，文档根指向 `/wwwroot` |
| POS 主库 | 只读账号（POS 系统中已存在），MySQL 5.5.47 |

> `mysqli` 不可省略 —— POS 主库是 MySQL 5.5，服务端**没有** `MAX_EXECUTION_TIME`，
> 只有 `mysqli` 的 `MYSQLI_OPT_READ_TIMEOUT` 能限制查询读取时间。
> `PDO::ATTR_TIMEOUT` 只管连接不管查询。

## 2. 目录与网络可见性

```
/opt/vip/
  wwwroot/          ← ★ 唯一网络可见目录，Web 文档根指向这里
    index.html        Pad 前端
    api.php           Pad API 入口
    assets/           Pad 静态资源
    cp/               管理后台（前端 + API 入口）
  app/              ← 网络不可见：全部业务逻辑
    config/config.php   实际配置（含账号密码，不入库）
    lib/  api/  cp/
  bin/              ← 网络不可见：CLI 入口
    init.php  cron.php  crontab.example
  db/               ← 网络不可见：DDL 与种子
  docs/             ← 网络不可见：设计文档
  tests/            ← 网络不可见
  var/log/          ← 网络不可见：日志
```

> ⚠️ **务必确认 `/app`、`/bin`、`/db`、`/docs`、`/tests` 不可从网络访问。**
> 最稳妥的做法是把文档根设为 `/opt/vip/wwwroot`，其余目录都在文档根之外。
> `bin/*.php` 另有 `PHP_SAPI !== 'cli'` 的兜底拒绝，但不要依赖它。

## 3. 安装步骤

### 3.1 配置

```bash
cp app/config/config.example.php app/config/config.php
vi app/config/config.php     # 填 store_code、两个数据库、短信/存储凭据
chmod 600 app/config/config.php
```

**主机地址、端口、账号全部是可变信息**（现场已发生过侧系统由
`192.168.58.128` 换到 `192.168.1.180`），一律走配置文件，代码内不硬编码。

### 3.2 建库 🔴 别跳过

**迁移文件里没有 `CREATE DATABASE`，也没有 `USE`** —— 库名是配置项
（`config.local_db.database`），写死在 SQL 里就没法改了。
所以库必须先手工建好，`bin/init.php` 与 phpMyAdmin 都一样。

```sql
CREATE DATABASE `vip_local`                 -- 换成 config 里的实际库名
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;               -- ★ 必须显式指定，见下

CREATE USER 'vip_app'@'127.0.0.1' IDENTIFIED BY '换成强口令';
GRANT ALL PRIVILEGES ON `vip_local`.* TO 'vip_app'@'127.0.0.1';
FLUSH PRIVILEGES;
```

> 🔴 **排序规则必须写 `utf8mb4_unicode_ci`,不能用服务器默认。**
> MariaDB 与 MySQL 5.7 默认 `utf8mb4_general_ci`、MySQL 8 默认
> `utf8mb4_0900_ai_ci`,没有一个等于建表用的 `utf8mb4_unicode_ci`,
> 会在 `WHERE 列 = @用户变量` 处报 `1267 非法混用`（详见 `db/README.md` §2.4）。

> ⚠️ **这是侧系统的本地库，不是 POS 主库。** 迁移与种子只作用于本地库，
> 任何情况下都不要对着 `coolroid` 执行。

**若用 phpMyAdmin 手工导入**（不推荐，见下）：必须先在左侧栏**点中该库**
再进 SQL 标签页，否则报 `#1046 No database selected`；
并按 `001` → `002` → `003` 的顺序导（003 依赖 001 建的 `pos_order`）。
导完还要手工补登记，否则下次 `migrate` 会重复执行并失败：

```sql
INSERT INTO `schema_migration` (`filename`,`applied_at`) VALUES
  ('001_init.sql',NOW()),('002_operator.sql',NOW()),('003_redeem.sql',NOW());
```

**推荐直接用 `php bin/init.php migrate`** —— 顺序、登记、安全闸门它都管。

### 3.3 环境自检

```bash
php bin/init.php check                    # 环境与连通性总览
sudo -u www-data php bin/diag.php         # ★ 用 Web 用户跑，定位连接问题
```

`diag.php` 专治「本地数据库暂时不可用」—— 页面上那句提示是统一兜底，
故意不显示连接串，六种完全不同的故障看起来一模一样。
`diag.php` 逐项试出来并给出对应的修复命令。

> 🔴 **务必用 Web 服务器的身份跑一遍。** MySQL 是按来源主机授权的，
> `'u'@'localhost'` 与 `'u'@'127.0.0.1'` 是两条不同的授权；
> 配置文件权限也可能只有 root 读得到。
> 「命令行连得上、网页连不上」绝大多数就是这两件事。

逐项检查 PHP 版本与扩展、配置完整性、两个数据库的连通性、主库时钟偏差、
关键表可读性。**POS 不可达只报警告不算失败** —— 降级路径仍可用。

### 3.4 建表与种子

```bash
php bin/init.php migrate     # 建表 / 增量升级
php bin/init.php seed        # 配置 + 餐期 + 套餐规则，幂等可重复
```

`migrate` 用 `schema_migration` 表记录已应用的迁移，**只跑没跑过的**，
因此上线后加新迁移（如 `003_redeem.sql`）可以直接执行，不会碰已有数据。
含 `DROP TABLE` 的迁移在库中有业务数据时仍然一律拒绝。

`seed` 会把种子里的门店码 `S001` 自动替换为配置中的 `store_code`。

### 3.5 创建管理员

```bash
php bin/init.php admin admin 系统管理员
# PIN 交互输入，不回显，至少 6 位
```

PIN 用 `password_hash`（bcrypt）存储，**不可逆、无法找回** —— 但可以重置：

| 场景 | 怎么做 |
|---|---|
| 自己想换 PIN | Pad 顶栏「改 PIN」/ 后台「操作员」页 → 需验旧 PIN |
| 员工忘了 PIN | 管理员在后台「操作员」页点「重置 PIN」→ 不需要旧 PIN，同时解除锁定 |
| **管理员自己忘了** | `php bin/init.php passwd <工号>` —— 需服务器 shell 权限 |

> 🔴 **`passwd` 是唯一管理员把自己锁死时的唯一恢复路径，别删。**
> 没有它的话：登不进后台建新管理员，`(store_code, login_name)` 唯一索引
> 又挡住同名重建，`audit_log` 按 `operator_id` 引用、删号会让历史审计成孤儿 ——
> 整个后台永久锁死。

改 PIN 或重置后，该账号的登录会话会被作废（自助修改保留当前这台设备），
PIN 疑似泄露时能把别人踢下线。所有改动都写审计日志。

### 3.6 定时任务

```bash
cp bin/crontab.example /tmp/vip-cron
vi /tmp/vip-cron            # 改 VIP 路径
crontab -u www-data /tmp/vip-cron
```

### 3.7 权限

```bash
chown -R www-data:www-data /opt/vip
chmod 600 app/config/config.php
mkdir -p var/log && chmod 750 var/log
```

## 4. Nginx 参考配置

```nginx
server {
    listen 443 ssl http2;
    server_name vip.example.com;      # 见 docs/00 §4：真实子域 + DNS 指内网 IP

    ssl_certificate     /etc/letsencrypt/live/vip.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/vip.example.com/privkey.pem;

    root /opt/vip/wwwroot;            # ★ 只暴露 wwwroot
    index index.html;

    # Pad API
    location /api.php { include fastcgi_params; fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/api.php;
        fastcgi_split_path_info ^(/api\.php)(/.*)$;
        fastcgi_param PATH_INFO $fastcgi_path_info; }

    # CP API
    location /cp/api.php { include fastcgi_params; fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root/cp/api.php;
        fastcgi_split_path_info ^(/cp/api\.php)(/.*)$;
        fastcgi_param PATH_INFO $fastcgi_path_info; }

    # 其余 .php 一律拒绝
    location ~ \.php$ { return 404; }

    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options DENY always;
    add_header Referrer-Policy same-origin always;
}

# HTTP 一律跳 HTTPS —— 会员手机号等 PII 不得在局域网内明文传输
server { listen 80; server_name vip.example.com; return 301 https://$host$request_uri; }
```

## 6. 日常运维

```bash
php bin/diag.php                   # 连接诊断（排障第一步）
php bin/cron.php status            # 水位线滞后与未处理告警
tail -f var/log/cron.log
tail -f var/log/php-error.log
```

后台「概览」页同样展示这些信息，水位线滞后超 72 小时会明确标红。

### 6.1 备份（硬性要求）

POS 主库只读 → 无法在 POS 上打「已积分」标记 → **本地库是幂等的唯一来源**。
本地库丢失会导致历史订单重复发分。

| 项 | 要求 |
|---|---|
| 频率 | 每日冷备 |
| 存储 | **异地**（利用「仅出站」的网络策略推到云端对象存储） |
| 加密 | 必须（含会员 PII） |
| 保留 | 30 天滚动 |
| 演练 | 定期恢复演练 |

## 7. 故障速查

| 现象 | 排查 |
|---|---|
| Pad 提示「POS 主库暂时无法访问」 | 收银流程**不受影响**，可走手工录入。查 POS 主机与网络，恢复后 Cron 会自动补抓 |
| 页面提示「本地数据库暂时不可用」 | 跑 **`php bin/diag.php`** 直接定位。这个提示是统一兜底（不泄露连接串），六种原因长得一样：口令错 / 用户不存在 / 库不存在 / 端口错 / 主机不可达 / **授权主机不匹配**。★ 一定要再用 Web 用户跑一遍 `sudo -u www-data php bin/diag.php` —— 「命令行好好的、网页就不行」几乎都是身份差异 |
| 输桌号查不到订单 | ① **优先改用小票号查**（小票 `Factura Simplificada` 那一行，最准且不受时间窗限制）② 是否超过 30 分钟窗口 ③ 是否外带（不积分）④ 用「放宽到 60 分钟」⑤ 仍无则手工录入 |
| 小票号查不到订单 | ① 核对输的是 `Factura Simplificada` 而**不是** `Número Ticket`（后者当日会重号）② 提示「超过 N 天」则是超出回溯上限，改后台 `invoice_lookup_max_days` 或走手工录入 |
| 后台水位线滞后 > 72 小时 | Cron 长期未成功。查 crontab、`var/log/cron.log`、锁文件 `/tmp/vip-cron/` |
| 告警「疑似 POS 数据缺失」 | **无法自愈** —— 数据本就不在主库里（实测 2024-08 曾整段丢失 6 天）。需人工核实并对该时段用手工录入补记 |
| 告警「菜单出现未归类的高价项」 | 到后台「套餐规则」页确认三个开关 |
| 收银员忘记 PIN | 管理员在后台「操作员」页点「重置 PIN」，不需要旧 PIN，同时解除连续失败锁定 |
| **管理员忘记 PIN**（登不进后台） | `php bin/init.php passwd <工号>`,交互输入新 PIN。这是唯一的恢复路径 |
| 账号被锁定（连续失败 5 次） | 等 15 分钟自动解锁；或管理员「重置 PIN」/「停用再启用」立即解锁 |
