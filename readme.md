### 餐厅 POS 旁会员积分系统方案优化报告

---

#### 一、 核心业务逻辑架构方案

针对您提出的需求与提供的 POS 数据库结构，整体系统的数据流转与业务方案设计如下：

**1. 目录结构规范**

* `/wwwroot`：网络可见目录，仅存放前端基础注册文件与公共静态资源。
* `/wwwroot/cp`：管理平台前端入口。
* `/app`：网络不可见目录，存放客户端核心业务逻辑、数据库连接与功能函数。
* `/app/cp`：管理平台核心后端代码。
* `/docs`：网络不可见目录，存放所有系统开发文档、接口说明与数据库字典，保持根目录绝对整洁。

**2. 订单关联与积分触发机制**

* **识别依据：** 系统通过 `history_order_head` 表中的 `order_head_id` 和 `check_id` 作为唯一订单识别号。


* **操作流程：**
1. 顾客结账后，收银员在 Pad 端输入顾客桌号（对应 `history_order_head` 的 `table_name` 或 `table_id`）以及会员识别信息（手机号、邮箱、或扫描 Apple/Google Wallet 电子卡二维码）。


2. 后端 `/app` 接收到请求后，对 POS 主数据库的 `history_order_head` 表发起**只读查询**。


3. 查询条件严格限定为：当前时间前 30 分钟内（此时间窗口后台可配）、对应桌号、且已结账状态（未结账订单剔除）的历史订单数据。


4. 匹配成功后，系统将获取到的 `order_head_id` 和 `actual_amount`（实际支付金额）写入本地独立会员数据库（Local DB），并根据后台配置发放对应积分。





**3. 退单与撤销的防刷机制 (核心难点突破)**
通过对 POS 数据库的分析，POS 系统在处理退菜或退单时，会将退款数据记录在历史表中。为了实现纯只读模式下的防刷分，建议采用**异步巡检方案**：

* **巡检机制：** 在 `/app` 目录下配置定时任务（Cron Job），定期读取 POS 主库中的 `history_order_head` 和 `history_order_detail` 表。


* **触发条件：** 系统遍历本地已积分的 `order_head_id`，比对 POS 库中该订单的 `return_amount` (退款金额) 字段。如果 `return_amount > 0`，或者在 `history_order_detail` 中检测到对应的 `is_return_item = 1`（代表存在退菜记录），则触发扣分动作。


* **闭环处理：** 侧边系统自动在本地会员库中生成一条“退款扣除积分”的流水，确保积分发放的严谨性。

#### 二、 后台管理 (CP) 规则配置模块

根据您的要求，后台 (`/app/cp`) 需包含以下灵活配置模块：

* **积分获取规则：**
* 基础规则：按次积分、按消费金额（如每 1 欧元=1 分）、或两者叠加。
* 积分倍率：支持针对不同时段或特定等级设置 1.2 倍、1.5 倍等乘数（默认设置 1 倍即为不启用）。


* **积分生命周期：**
* 支持三种模式切换：1. 每年固定日期清零（如年底）；2. 自获取日起 XX 天过期；3. 动态延期（自获取日起 XX 天过期，但一旦有新消费，账户内所有积分有效期自动顺延 XX 天）。


* **等级与保级系统：**
* 等级设定：银卡、金卡、白金卡、黑金卡、钻石卡。
* 保级机制（可停用）：开启后，可设置“规定周期内消费满 X 元或积累 X 分维持当前等级”，否则自动降级。


* **卡券模块：**
* 赠券、发券及有效期管理。核销动作严格在 Pad 端进行本地库标记，收银员在 POS 端手动做对应的折扣收银。

#### 三、 账户体系与西班牙合规 (GDPR/LOPDGDD) 注意事项

既然不涉及微信，且由收银员通过 Pad 录入用户信息，且需满足西班牙数据保护法案（LOPDGDD）的合规性，在方案设计上必须做出以下合规部署：

* **极简录入：** 遵循数据最小化原则，仅选填手机号、邮箱、生日，无需姓名。
* **合规授权（必须补齐）：**
* 由于是收银员代为注册，系统在创建会员档案的瞬间，**必须**自动向用户提供的手机号（发送 SMS）或邮箱发送一条带有隐私政策链接的通知。
* 该链接内应包含明确的“取消订阅/要求删除数据”的按钮。如果收银员扫描的是 Apple/Google Wallet，生成电子卡时也必须在卡片背面的描述栏（Passbook Back Fields）附上完整的隐私条款链接。否则，在西班牙当地处理未经用户主动勾选同意的 PII（个人身份信息）将面临极高的合规风险。
